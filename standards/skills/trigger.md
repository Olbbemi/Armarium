# 발동 조건 규칙

`description` 필드에 적용한다.

## T1

공용 스킬의 프론트매터는 `name` 과 `description` 만 쓴다.

**판정 기준** -- `name` 과 `description` 이 둘 다 있어야 한다. 다른 키가 있으면
위반이다. 검사 C1 이 판정한다. 클로드 전용 키가 필요하면 S9 를 따른다.

**근거** -- 코덱스가 지원하는 키는 `name` 과 `description` 뿐이다. 다른 키는
코덱스에서 동작을 만들지 않고, 지금 조용히 무시되는 것도 보장이 아니다.

## T2

무엇을 하는가와 언제 쓰는가를 둘 다 담는다.

**판정 기준** -- 둘 중 하나가 없으면 위반이다. 사람이 판정한다.

**근거** -- `description` 은 자동 발동의 유일한 근거다. 하나만 있으면 모델이
지금 상황에 맞는 스킬인지 판단할 수 없다.

## T3

요청 문장을 적고 거기서 트리거를 뽑는다.

**판정 기준** -- 사람이 판정한다. 셋을 본다.

1. `requests.md` 에 이 스킬을 모르는 사용자가 그 상황에서 할 법한 요청 문장이
   세 개에서 다섯 개 있는가
2. `description` 의 트리거가 그 문장들에서 나왔는가
3. 그 스킬을 이미 아는 사람만 쓰는 말이 트리거에 있는가. 스킬 이름, 내부 용어,
   분류명이 여기 해당하고 하나라도 있으면 위반이다

```
분류명 (위반)          상황 어휘 (통과)
스킬 규격 검증         스킬이 발동을 안 한다
스킬 작성 워크플로     스킬 하나 만들어야 하는데
```

**근거** -- 자동 발동은 사용자 발화와 `description` 을 견주는 모델 판단이다.
분류명은 사용자가 쓰지 않는 말이라 겹치지 않는다. 작성 순서는 산출물에 흔적이
남지 않아 판정할 수 없으므로 순서의 결과물인 `requests.md` 로 판정한다.

## T4

절차나 워크플로를 요약하지 않는다.

**판정 기준** -- 사람이 판정한다.

```
위반:  목적 확정부터 검사 통과와 사용자 승인까지 진행한다
통과:  스킬 작성 절차와 규격, 기계 검사를 제공한다
```

**근거** -- `description` 은 발동 여부를 판단하는 데만 쓰인다. 절차는 발동한 뒤
본문에서 읽으므로, 여기 넣으면 매 세션 비용만 낸다.

## T5

`description` 은 1024자를 넘지 않는다.

**판정 기준** -- 길이가 1024자를 넘으면 위반이다. 검사 C2 가 판정한다.

**근거** -- 클로드의 상한이다.
