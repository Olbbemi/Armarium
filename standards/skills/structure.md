# 뼈대 규칙

파일 배치와 `name`, 매니페스트에 적용한다.

## 기본 배치

```
skills/<이름>/
  SKILL.md          진입점
  requests.md       요청 문장. description 의 원재료
```

규격과 검사는 스킬 밖에 있고 모든 스킬이 함께 쓴다.

```
standards/skills/   단계에서만 읽는 규격
checks/             기계 검사
```

## S1

`name` 은 디렉토리 이름과 같다.

**판정 기준** -- 두 값이 다르면 위반이다. 검사 C3 이 판정한다.

**근거** -- 두 값이 다르면 어느 이름으로 불리는지 알 수 없다.

## S2

진입점에서 도달할 수 없는 파일을 두지 않는다.

**판정 기준** -- 모든 `SKILL.md` 를 시작점으로 상대 링크를 따라갔을 때 닿지 않는
마크다운이 있으면 위반이다. 대상은 스킬 디렉토리와 `standards/` 아래의 마크다운이고
`SKILL.md` 자신은 뺀다. 저장소 밖으로 나가는 링크는 따라가지 않는다. 그 링크 자체는
S3 이 판정한다. 검사 C5 가 판정한다.

**근거** -- 도달하지 못하는 파일은 로드되지 않는다. 규격 문서가 서로를 가리키며
여러 단계로 이어지므로 직접 참조만 보면 정상 구조를 고아로 판정한다.

## S3

상대 링크의 대상이 저장소 안에 파일로 존재한다.

**판정 기준** -- 링크는 `[이름](경로)` 표기만 쓴다. 참조형 정의, 꺾쇠로 감싼 경로,
퍼센트 인코딩은 위반이다. 표기가 맞으면 대상을 보고 저장소 밖이거나 없거나 파일이
아니면 위반이다. 앵커와 쿼리는 잘라 내고 경로만 본다. 검사 대상은 스킬 디렉토리와
`standards/` 아래 마크다운의 링크다. 검사 C4 가 판정한다.

**근거** -- 깨진 링크는 절차를 그 자리에서 끊는다. 저장소 밖 파일은 플러그인에
따라가지 않으므로 설치된 곳에서 없는 것과 같다. 표기를 하나로 고정하면 마크다운
문법을 넓게 해석하지 않아도 되고, 파일명에 공백을 쓰지 않으면 나머지 표기가
필요 없다.

## S4

부속 파일은 하네스가 스캔하지 않는 위치에 둔다.

**판정 기준** -- `skills/` 바로 아래에 파일이 있거나, `skills/` 아래 디렉토리에
`SKILL.md` 가 없으면 위반이다. 검사 C6 이 판정한다. 스킬 디렉토리 안의 하위
디렉토리는 스캔 대상이 아니므로 자유롭게 쓴다.

**근거** -- 스캔 디렉토리에 등록물이 아닌 파일이 섞이면 하네스가 그것을 등록물로
읽으려 한다.

## S5

항상 필요한 것은 `SKILL.md` 에, 특정 단계에서만 필요한 것은 참조 파일에 둔다.

**판정 기준** -- 사람이 판정한다. 그 내용을 안 읽고도 다음 단계로 갈 수 있으면
참조 파일에 둔다. 참조 파일은 `SKILL.md` 안의 다른 절이 아니라 별도 파일이다.

**근거** -- 스킬이 발동하면 `SKILL.md` 는 통째로 로드된다. 별도 파일이어야 그
단계에 도달했을 때만 읽힌다.

## S6

매니페스트 세 곳의 `name` 과 `version` 이 일치한다.

**판정 기준** -- `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`,
`.claude-plugin/marketplace.json` 의 값이 다르면 위반이다. 검사 C9 가 판정한다.
`description` 은 하네스마다 다를 수 있으므로 검사하지 않는다. 마켓플레이스에
플러그인이 둘 이상이 되면 이름으로 짝지어 비교하도록 C9 를 고친다.

**근거** -- 하네스마다 자기 매니페스트를 요구하므로 피할 수 없는 중복이다.
어긋나면 어느 것이 맞는지 알 수 없다.

## S7

매니페스트가 가리키는 경로가 실제로 존재한다.

**판정 기준** -- 매니페스트에 적힌 경로에 대상이 없으면 위반이다. 검사 C10 이
판정한다.

**근거** -- 경로가 어긋나면 플러그인이 통째로 안 실리는데 에러 없이 조용히
안 된다.

## S8

검증 단위마다 이력이 있고 현재 모든 파일의 최신 해시와 일치한다.

**판정 기준** -- 검증 단위는 저장소 구조에서 산출한다. `standards/skills`, `checks`,
`skills/` 아래의 각 스킬 디렉토리다. 단위에 이력이 없거나, 단위 아래 파일이 이력에
없거나, 해시가 다르면 위반이다. 기록의 `target` 이 저장소 안의 상대 디렉토리가
아니거나, 실제 디렉토리가 아니거나, 다른 기록과 겹치거나, 검증 단위가 아니어도
위반이다. 대상 파일이 저장소 밖을 가리켜도 위반이다. 기록이 저장소 `CLAUDE.md` 의
검증 이력 절이 정한 형식과 다르면 위반이고, 그 절이 정한 항목을 모두 본다. 검사
픽스처도 대상이고 `__pycache__` 아래 파일은 아니다. 검사 C11 이 판정한다.

**근거** -- 이력 파일에서 단위를 찾으면 이력을 안 만든 단위가 검사 없이 통과한다.
검증 기록만 있으면 그 뒤에 고쳐도 검증받은 것처럼 보인다.

## S9

클로드 전용 프론트매터 키가 필요하면 순서대로 시도한다.

**판정 기준** -- 사람이 판정한다. 위에서부터 시도하고 안 되면 다음으로 간다.

1. 그 키 없이 본문 지시로 되는지 본다
2. 코덱스 쪽 대응 설정을 사이드카 파일로 붙여 해결되는지 본다
3. 그 스킬만 예외형으로 나눈다. 공용 본문을 스캔 대상이 아닌 위치에 두고
   `claude/skills/<이름>/SKILL.md` 와 `codex/skills/<이름>/SKILL.md` 가 그것을
   읽는다. 두 파일의 `description` 이 다르면 위반이다
4. 클로드에서만 의미 있는 스킬이면 클로드 전용으로 둔다

**근거** -- 예외형은 파일이 셋으로 늘고 `description` 이 두 곳에 생긴다. 먼저
안 나누고 되는 길을 확인한다.
