# 흐름 B — 기존 코드 변경

---

## 적용 상황

이 variant 는 다음 두 조건을 모두 만족할 때 적용된다.
- 2단계 산출물의 "적용 흐름"이 B (기능 추가 / 리팩터링 / 둘 다)
- 변경 대상 코드 트리가 이미 존재함

---

## 흐름별 사전 조사

메인 파일의 사전 조사(핸드오프 로드, 외부 검색, 사용자 확인)가 끝난 뒤 추가로 다음 항목을 확인한다.

### 1. 기존 컨벤션 파악

- 디렉토리 / 파일 명명 규칙
- 포맷팅 규칙 (린터 / 포맷터 설정)
- 테스트 파일 위치 / 명명 규칙
- 모듈 간 import / include 컨벤션

언어 reference 의 표준과 다른 컨벤션이면, 기존 컨벤션을 우선 따른다.

### 2. 빌드 / 테스트 명령 확인

CI 설정 / Makefile / pyproject.toml / Cargo.toml / CMakeLists.txt 등에서 표준 빌드·테스트 명령을 추출한다.
명령이 명확하지 않으면 사용자에게 질문 (공통 원칙 1).

### 3. baseline 테스트 실행

변경 전 전체 테스트를 실행해 baseline (변경 전 통과 상태) 을 확보한다.

<PENETRATE>
변경 작업 시작 전 baseline 테스트 결과를 산출물의 "구현 결과 - baseline" 섹션에 기록한다.
</PENETRATE>

<RICOCHET>
baseline 확인 없이 변경 작업을 시작하지 않는다.
</RICOCHET>

baseline 에 이미 실패 테스트가 있다면, 사용자에게 다음 중 어느 것인지 확인 (공통 원칙 1):
- 이미 알려진 실패 (이번 작업과 무관) -> 기록만 하고 진행
- 처음 발견된 실패 -> 5단계(디버깅) 진입 검토

### 4. 변경 지점 주변 코드 / 의존 관계 재확인

2단계의 "현재 상태" 섹션을 코드 수준에서 다시 확인한다 (코드가 그 사이 변경됐을 수 있음).

---

## 흐름별 작업 흐름

다음 두 단계로 진행한다.

### 단계 1 — TDD 사이클 (회귀 방지 케이스 포함)

2단계 TDD 계획의 모든 케이스를 다음 사이클로 처리한다.

1. **Red:** 변경 사항을 검증할 테스트 + 회귀 방지 케이스를 작성. 실패 확인
2. **Green:** 테스트가 통과하는 최소 변경
3. **Refactor:** 기존 컨벤션에 맞춰 정리, 전체 테스트(baseline 포함) 재실행으로 통과 유지 확인

<PENETRATE>
Red 단계에서 테스트가 실제로 실패하는 것을 확인한 뒤 Green 으로 진입한다.
</PENETRATE>

<RICOCHET>
테스트 실패 확인 없이 Green 단계로 진입하지 않는다.
</RICOCHET>

<RICOCHET>
회귀 방지 케이스 없이 변경을 진행하지 않는다.
</RICOCHET>

<RICOCHET>
Refactor 단계에서 baseline 테스트가 깨지면 즉시 롤백하고, 원인 파악 없이 다음 사이클로 진행하지 않는다.
</RICOCHET>

<RICOCHET>
기존 컨벤션과 다른 스타일을 사용자 협의 없이 도입하지 않는다.
</RICOCHET>

### 단계 2 — 통합 빌드·테스트

모든 사이클이 끝난 후 전체 빌드·테스트를 실행해 baseline 테스트가 변경 후에도 모두 통과하는지 확인한다.
실패 시 5단계(디버깅) 진입.

---

## 흐름별 산출물 보완

메인 파일의 "산출물 형식" 템플릿에 다음 항목을 추가 채운다.

- "구현 결과" 섹션 아래 "변경 지점" 항목:
  - 변경된 파일과 변경 요약
  - 신규 추가 / 삭제된 파일
- "구현 결과" 섹션 아래 "baseline" 항목:
  - 변경 전 baseline 테스트 결과 (통과 / 실패 케이스)
- "TDD 사이클 기록" 섹션 아래 "회귀 방지 케이스" 항목:
  - 추가한 회귀 방지 테스트 목록

리팩터링이 포함된 경우 추가:
- "구현 결과" 섹션 아래 "전환 경로 진행" 항목:
  - 2단계 "전환 경로"의 각 단계 진행 상태 + 각 단계 종료 시점의 동작 상태

## 흐름별 완료 기준

메인 파일 완료 기준 체크리스트의 "흐름 variant 파일의 흐름별 완료 기준이 충족됨" 항목은 다음 세부 항목을 모두 충족함을 의미한다.

- [ ] baseline 테스트(변경 전 통과 테스트) 가 변경 후에도 모두 통과함
- [ ] 추가된 회귀 방지 케이스가 모두 통과함
- [ ] 기존 컨벤션이 유지됨 (변경 사유가 있으면 산출물에 기록됨)
- [ ] (리팩터링인 경우) 2단계 "전환 경로"의 모든 단계가 동작 가능 상태를 유지함
- [ ] TDD 사이클이 모든 케이스에 대해 Red -> Green -> Refactor 순서로 진행됨
