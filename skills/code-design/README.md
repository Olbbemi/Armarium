# code-design

새 기능·서비스 개발의 설계부터 구현·문서화까지를 단계로 나눈 **개발 파이프라인 지도** 스킬.

## 무엇을 하나

전체 개발 흐름을 9단계로 정의하고, 각 단계의 목적·완료 기준·단계 전환 규칙을 제공한다. 지금 어느 단계인지 판단하고, 그 단계의 진입 파일로 안내한다.

## 언제 쓰나

`/code-design` 호출, 또는 "어디서부터 시작해?", "지금 뭐 해야 해?", "전체 흐름이 어떻게 돼?" 처럼 새 개발의 시작점·현재 단계·다음 작업 파악이 필요할 때.

## 구조

- `overview.md` — 파이프라인 지도(진입점). 어느 단계든 **먼저 읽고** 진입
- `00-principles.md` — 모든 단계 공통 원칙 (하위 단계는 여기 원칙을 재기술하지 않고 참조만)
- 단계별 진입 파일
  - `01-requirements.md` — 요구사항 분석
  - `02-design.md` — 설계 (`02-design/new_project.md`, `02-design/extend_or_refactor.md` 분기)
  - `03-implementation.md` — 구현. 분기 구조가 아니라 경량 "최소 제약" 가드레일(G1~G12) 묶음 (언어 고유 가드레일은 `03-implementation/languages/cpp.md`)
  - `04-static-analysis` ~ `09-documentation` — TBD(미작성)

## 9단계와 정상 흐름

```
1 요구사항 → 2 설계 → 3 구현 → 4 정적분석/리팩터링 → 7 테스트 → 8 코드리뷰 → 9 문서화

5 디버깅 / 6 보안검토 — 어느 단계에서든 이슈 발생 시 진입, 해결 후 원래 단계로 복귀
```

| 단계 | 목적 |
|------|------|
| 1 요구사항 분석 | 해결할 문제와 범위를 명확히 |
| 2 설계 | 아키텍처·모듈 구조·인터페이스 확정 (+ TDD 계획) |
| 3 구현 | 설계 기반 동작 코드 작성 |
| 4 정적분석/리팩터링 | 품질·구조 개선 |
| 5 디버깅 | 버그 원인 파악·수정 (수시 진입) |
| 6 보안 검토 | 취약점 탐지·해소 (수시 진입) |
| 7 테스트 | 요구사항 충족 검증 |
| 8 코드 리뷰 | 다른 관점에서 품질 점검 |
| 9 문서화 | 코드·설계를 문서로 남김 |

## 단계 전환 규칙

각 단계 종료 시 완료 기준 체크리스트와 피드백 칸을 제시한다.

- 모든 항목 체크 + 피드백 없음 → 다음 단계 진입
- 피드백이 있으면 → 반영 후 재제시

단계별 완료 기준 상세는 `overview.md` 의 "각 단계 요약 및 완료 기준" 참조.

## 산출물 저장 경로

모든 단계 산출물은 **프로젝트 루트(= Claude 실행 디렉토리 CWD)** 기준으로 저장된다. 프로젝트 루트에 대해 별도 확인을 받지 않는다. 구체적 경로 패턴은 `00-principles.md` 의 "단계 산출물 저장 정책" 참조.
