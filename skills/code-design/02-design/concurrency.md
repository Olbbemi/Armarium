# 동시성 설계 (concurrency)

공유 가변 상태에 대한 동시/인터리빙 접근이 있는 설계에서, 놓치면 구현 단계에서 문제가 되는 hazard 를 빠짐없이 짚고 각각의 대응을 설계 시점에 결정하기 위한 파일. 상류(02-design.md)의 게이트가 이 파일을 로드하기로 판정했을 때만 열린다.

대상 범위: 멀티스레드 / async 인터리빙 + 공유 메모리형 IPC(shm, mmap, 프로세스 간 동기화). 경계 너머 메시지 전달(네트워크, 파이프, 큐)은 이 파일이 아니라 `communication.md` 가 담당한다.

---

## 1. hazard 체크리스트

로드 여부는 상류가 이미 정했다. 여기서는 아래 표의 **각 항목이 이 설계에 해당하는지**를 항목마다 판정한다. 트리거 · 키워드는 대응을 정하기 위한 검토 단서이지 처방이 아니다 -- 구체 값은 이 설계의 요구 · 제약에 맞춰 논의해 정한다.

<PENETRATE>
hazard 표의 각 항목을 해당 / N-A 로 명시적으로 판정한다.
</PENETRATE>

<RICOCHET>
해당하는 hazard 를 키워드만 나열하고 대응 결정 없이 넘어가지 않는다.
</RICOCHET>

| hazard | 언제 걸리나 (트리거) | 검토 키워드 / 패턴 |
|--------|---------------------|---------------------------|
| 공유 가변 상태 레이스 (data race) | 공유 가변 상태에 둘 이상 맥락이 접근하고, 그중 최소 하나가 write (read-only 공유는 해당 없음) | 뮤텍스 / 락, 불변(immutable) 데이터, 스레드 로컬, 원자적 연산(atomic) |
| 원자성 위반 (복합 연산) | 개별 연산은 각각 안전해도, read-modify-write / check-then-act 처럼 묶여야 할 복합 연산이 쪼개져 그 사이 끼어듦 | CAS(compare-and-swap), 임계구역, 트랜잭션 |
| 데드락 / 라이브락 | 락을 둘 이상 중첩 획득(순환 대기) 또는 같은 락 재진입, 또는 서로 양보 / 재시도로 진행 불가(라이브락) | 락 순서 규약(lock ordering), 락 계층, 타임아웃 락, try-lock, 재진입 락, backoff + jitter |
| 메모리 가시성 / 재정렬 | 동기화 프리미티브(락 / 고수준 채널) 없이 원자 변수 · 플래그로 직접 스레드 간 신호 / 데이터를 주고받아, 쓴 값의 가시성 · 순서가 보장 안 됨 (락으로 감싼 공유는 대체로 해당 없음) | 메모리 배리어, atomic, happens-before, acquire / release |
| 실행 순서 / 조정 (coordination) | 여러 맥락이 정해진 순서 / 시점에 만나야 함 -- 완료 대기, 생산자 - 소비자, 초기화 후 개시 등 (틀리면 준비 전 조기 진행 또는 lost wakeup) | 조건변수, 배리어, 래치, 세마포어, future / promise, while 루프로 조건 재확인, lost / spurious wakeup |
| 라이프사이클 / 취소 / 종료 | 실행 맥락의 생성 - 취소 - 종료를 다뤄야 함 -- graceful shutdown 시 종료되지 않고 멈춤, 취소가 하위로 전파 안 됨, join / await 누락으로 정리 안 된 맥락 잔존 · 결과 · 예외 유실 | 취소 토큰, join, 스레드풀 종료, 인터럽트, 구조적 동시성(structured concurrency), 예외 전파 |
| 프로세스 간 동기화 (공유메모리 IPC) | 공유 메모리 / mmap 또는 프로세스 간 동기화 프리미티브를 여러 프로세스가 공유 -- 스레드 hazard(레이스 / 원자성 / 가시성 / 조정)가 프로세스 경계에서 재현되고, 락 소유 프로세스가 죽으면 락이 영영 안 풀림 · 커널 / FS 객체 정리 책임이 더해짐 | named semaphore, 파일 락(flock), robust mutex, 소유 프로세스 종료 시 락 처리 |
| 싱글스레드 async 인터리빙 / 재진입 | 싱글스레드 async 라도, await / yield 로 양보한 사이 다른 태스크가 끼어들어 공유 상태가 바뀜 -- check-then-act 가 await 를 사이에 두면 깨짐. 이벤트 / 콜백 재진입 포함 | await 로 임계 구간을 쪼개지 않기, await 후 상태 재검증, 재진입 가드, async 뮤텍스 |

## 2. 산출물 기록

해당하는 각 hazard 의 대응 결정을 02-design 산출물의 `## 동시성 설계` 전용 섹션에 남긴다.

```markdown
## 동시성 설계
(concurrency.md 로드 시. 아니면 N/A)
| hazard | 해당 | 대응 결정 |
|--------|------|----------|
| 공유 가변 상태 레이스 | 해당 | 상태 X 를 뮤텍스 M 으로 보호, 임계구역은 ... |
| 데드락 | N-A | 락이 하나뿐이라 순환 대기 없음 |
```

</PENETRATE>
