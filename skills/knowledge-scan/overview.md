# 코드 스캔 캡처

사용자의 명시 명령으로 대상 코드베이스를 훑어, 쓰인 비자명 문법을 후보로 뽑고 사용자가 골라 wip 로 캡처하는 스킬.

명령 한 번에 시작해 끝나는 단발 작업이다. 대화를 상시 감시하는 `knowledge-capture` 와는 수명주기가 다르므로 별도 스킬로 둔다.

wip 를 확정지식으로 올리는 승급은 별도 스킬 `knowledge-promote` 가 담당한다. 본 스킬은 캡처까지만 다룬다.

---

## 활성 조건

`knowledge-scan` 은 사용자가 `/knowledge-scan` 슬래시 명령으로 명시적으로 호출했을 때만 활성된다.

<RICOCHET>
LLM 자가판단으로 스킬을 활성하거나 스캔을 시작하지 않는다.
</RICOCHET>

---

## 공용 프로토콜

저장 경로 검증 · `knowledge-writer` 호출 형태 · 입력 포맷 · 반환 본문 저장은 아래 공용 파일이 단일 출처다.

    references/knowledge-wip-protocol.md

활성 직후 이 파일을 Read 툴로 로드해 따른다. 본 스킬이 받는 경로는 wip 저장 디렉토리 하나이며, 공용 파일 1절의 검증 절차를 그 경로에 적용한다.

<PENETRATE>
활성 직후 `references/knowledge-wip-protocol.md` 를 Read 툴로 로드하고, wip 저장 디렉토리 경로를 입력받아 그 파일의 검증 절차를 적용한다.
</PENETRATE>

## 하위 스킬

| 파일 | 역할 |
|------|------|
| `skills/knowledge-scan/languages/<lang>.md` (현재 `cpp.md`) | 언어별 "정리할 만한 비자명 문법" 목록. 스캐너가 로드해 코드와 대조 |
| `references/knowledge-wip-protocol.md` | 세 knowledge 스킬 공용 -- 경로 검증 · writer 호출 · 저장 규칙 |

에이전트 2개를 쓴다. 정의 파일은 플러그인 루트 `agents/` 에 있다.

| 에이전트 | 파일 | 역할 |
|----------|------|------|
| `knowledge-code-scanner` | `agents/knowledge-code-scanner.md` | 코드베이스 순회 + 문법 사용처 탐지 + 파일명 dedup 후 후보 목록 반환 |
| `knowledge-writer` | `agents/knowledge-writer.md` | 메인의 입력을 받아 wip 본문을 작성하고 반환 (저장은 메인이 수행) |

## 실행 순서

1. 활성 (슬래시 명령). 공용 프로토콜을 로드하고 wip 저장 경로를 확정한다
2. 스캔 명령 판정 (`발동 규칙`)
3. 스캔 대상 경로 확보 (`스캔 대상 경로`)
4. 언어 판정 (`언어 판정`)
5. `knowledge-code-scanner` 호출 -- 포그라운드. 입력: `codebase_path` / `language` / `catalog_path` / `knowledge_glob` / `wip_glob`. 출력: 후보 목록을 최종 메시지로 반환
6. 후보 게이트 -- 사용자가 캡처할 topic 을 고른다
7. 고른 topic 마다 `knowledge-writer` 호출 -- 백그라운드 (`run_in_background: true`). 입력: `writer 위임` 의 값. 출력: wip 본문을 반환 -> 메인이 `<저장경로>/<권장파일명>` 으로 저장

### 단계 시각화 (TaskCreate)

- 대상 경로 확보 · 언어 판정 같은 짧은 준비는 task 로 만들지 않는다
- 스캐너 호출(포그라운드) -- 시작 시 in_progress, 반환 시 completed
- 후보 게이트 -- 사용자에게 확인 요청 직전 completed, 응답 후 다음 task in_progress
- writer 호출(백그라운드) -- 호출 즉시 completed ("위임 완료"). subject 는 "knowledge-writer 에이전트 호출" 형식. 고른 topic 마다 하나씩

## 발동 규칙

스캔은 사용자가 코드베이스 스캔을 명시적으로 명령했을 때만 발동한다. 발동 신호는 자연어 발화로 인식하며, 별도 문법·인자를 요구하지 않는다.

### 진짜 스캔 명령의 3요소

한 발화가 스캔 명령인지는 아래 세 요소가 뚜렷이 모였는지로 가른다.

| 요소 | 뜻 | 아닌 예 |
|------|----|--------|
| 동작 | 훑기 / 스캔 / 조사 (쓸어보라는 의도) | "이 코드 봐줘 / 설명해줘 / 리뷰해줘" |
| 대상 | 코드베이스 / 디렉토리 / 코드 전반 | 대화 속 스니펫 하나 |
| 목적 | 쓰인 문법·기능을 뽑아 정리·캡처 | 버그 찾기 / 성능 분석 |

### 3단 처리

- **3요소가 다 뚜렷** ("이 코드베이스 문법 스캔해줘", "여기 쓰인 비자명 문법 뽑아줘") -- 확인 없이 발동한다. 이미 명시적이라 되묻는 것은 군더더기다.
- **일부만 있거나 모호** ("이 코드 좀 봐줘", "여기 뭐 쓰였나 볼까") -- 한 줄로 확인한 뒤에만 발동한다 ("코드베이스 문법 스캔을 돌릴까요?").
- **스캔 의도가 없음** (설명·리뷰·특정 함수 질문) -- 무시한다.

<RICOCHET>
일반 대화의 코드 언급만으로 스캔을 자동 발동하지 않는다. 스캔 의도가 모호한데 확인 없이 발동하지 않는다.
</RICOCHET>

<PENETRATE>
스캔 의도가 모호하면 한 줄로 확인한 뒤에만 발동한다.
</PENETRATE>

## 스캔 대상 경로

스캔할 코드베이스 경로는 항상 명시적으로 확보한다. 현재 작업 디렉토리가 곧 소스라고 가정하지 않는다 -- 저장 경로를 활성 시 입력받는 것과 같은 취지다.

- 스캔 명령에 대상 경로가 담겼으면("src/ 스캔해줘") 그 경로를 쓴다.
- 담기지 않았으면("이 코드베이스 스캔해줘") 대상 경로를 한 줄 물어 받는다. 이는 확인 게이트가 아니라 필수 입력 수집이므로, 발동 규칙의 즉시 발동과 충돌하지 않는다.

이 경로가 스캐너 입력 `codebase_path` 가 된다. 저장 경로(Herbarium wip)와는 별개다.

<PENETRATE>
스캔 대상 경로를 명시적으로 확보한 뒤에 스캐너를 호출한다. 명령에 없으면 물어 받는다.
</PENETRATE>

## 언어 판정

스캐너는 언어별 카탈로그(`languages/<lang>.md`)를 기준으로 돌기 때문에, 대상의 언어를 먼저 정한다.

### 절차

1. 대상 경로의 파일 확장자를 훑어 어떤 언어들이 있는지 감지한다.
2. 감지된 언어를 보유 카탈로그(`skills/knowledge-scan/languages/` 하위 `<lang>.md` 존재분)와 교차한다.
3. 감지 결과를 사용자에게 확인받은 뒤 스캔 언어를 확정한다.

### 확인 방식

- **카탈로그 보유 언어 하나** -- "이 코드베이스는 <lang> 인 것 같은데, 이걸로 스캔할까요?" 로 확인한다.
- **카탈로그 보유 언어 여럿** -- "이 코드베이스에 <lang1>, <lang2> 가 보이는데, 전부 스캔할까요, 일부만 할까요?" 로 확인한다.
- **카탈로그 없는 언어가 섞임** -- 그 언어는 카탈로그가 없어 스캔할 수 없음을 함께 알린다. 카탈로그 있는 언어만 대상이 된다.
- **카탈로그 보유 언어가 하나도 없음** -- "스캔 가능한 언어(카탈로그 보유)가 없습니다" 를 알리고 스캔을 중단한다.

사용자가 특정 언어를 콕 집어 명령했으면(그 언어 카탈로그가 있으면) 감지보다 그 지정을 우선한다.

확정된 언어마다 그 언어의 `skills/knowledge-scan/languages/<lang>.md` 절대경로가 스캐너 입력 `catalog_path` 가 된다. 언어가 여럿이면 언어당 스캐너를 각각 호출한다.

<PENETRATE>
감지한 언어는 사용자에게 확인받은 뒤 스캔 언어로 확정한다.
</PENETRATE>

<RICOCHET>
카탈로그가 없는 언어를 스캔 대상으로 삼지 않는다.
</RICOCHET>

## 스캐너 호출

언어가 확정되면 언어마다 `knowledge-code-scanner` 에이전트를 호출해 후보 목록을 받는다.

### 호출 형태

| 항목 | 값 |
|------|----|
| 호출 도구 | Task |
| `subagent_type` | `knowledge-code-scanner` |
| `run_in_background` | `false` (포그라운드) |
| 스캐너 출력 | 후보 목록을 최종 메시지로 반환 (파일 저장 안 함) |

스캐너 호출은 포그라운드로 한다. 반환된 후보를 곧바로 사용자 게이트에 써야 하므로, 완료를 기다렸다가 다음 단계로 간다. writer 호출이 백그라운드인 것과 대비된다 -- writer 는 게이트 이후 단계다.

<PENETRATE>
`knowledge-code-scanner` 호출은 포그라운드(`run_in_background: false`)로 한다. 반환된 후보 목록으로 곧바로 후보 게이트를 돌린다.
</PENETRATE>

### 스캐너 입력 포맷

Task 도구의 prompt 파라미터에 라벨 + 콜론 구조화 텍스트로 전달한다. JSON 형식은 쓰지 않는다.

| 필드 | 값 |
|------|----|
| `codebase_path` | 스캔 대상 경로 (`스캔 대상 경로` 에서 확보) |
| `language` | 확정 언어 (예: `cpp`) |
| `catalog_path` | 그 언어의 `skills/knowledge-scan/languages/<lang>.md` 절대경로 |
| `knowledge_glob` | dedup 대조용 확정지식 Glob. 저장 경로가 속한 Herbarium 저장소의 `knowledge/**/*.md` |
| `wip_glob` | dedup 대조용 wip Glob. 같은 Herbarium 저장소의 `wip/*.md` |

`knowledge_glob` / `wip_glob` 은 활성 시 확보한 저장 경로가 속한 Herbarium 저장소 루트에서 구성한다. 스캐너는 이 Glob 으로 파일명만 대조해 이미 정리된 topic 을 후보에서 뺀다(본문은 안 읽음).

## 후보 게이트

스캐너가 반환한 후보 목록을 사용자에게 제시하고, 어떤 것을 wip 로 캡처할지 고르게 한다. 이것이 이 스킬의 유일한 사용자 질문이다.

- 후보마다 `topic` · `usages`(실측 <=3개) · `why` 를 함께 보여 사용자가 판단할 근거를 준다.
- 사용자는 여럿을 한 번에 고를 수 있다. 고른 topic 각각을 캡처 대상으로 확정한다.
- 스캐너가 "카탈로그 보강 후보"(카탈로그 밖 발견)를 붙였으면 정식 후보와 구분해 참고로만 보여준다. 이는 사람이 카탈로그에 추가할지 판단할 몫이며, 이 게이트의 캡처 선택지로 올리지 않는다.
- 후보가 없으면("정리할 신규 비자명 문법 없음") 그대로 알리고 종료한다. writer 를 호출하지 않는다.

<PENETRATE>
스캐너 후보 목록을 사용자에게 제시하고, 사용자가 고른 topic 만 캡처 대상으로 확정한다.
</PENETRATE>

<RICOCHET>
사용자가 고르지 않은 후보를 임의로 캡처하지 않는다. "카탈로그 보강 후보" 를 정식 캡처 대상으로 올리지 않는다.
</RICOCHET>

## writer 위임

사용자가 고른 topic 마다 `knowledge-writer` 를 호출해 wip 본문 작성을 위임한다. 호출 형태·입력 포맷·저장 책임은 공용 프로토콜 2절·3절을 그대로 따른다. 여러 topic 을 골랐으면 각각 백그라운드로 위임한다.

이 스킬이 채우는 입력값은 다음과 같다.

| 필드 | 이 스킬의 값 |
|------|-------------|
| `save_path` | 활성 시 확보한 저장 경로 |
| `topic` | 카탈로그의 정식 명칭 그대로 |
| `triggered_by` | `code-scan` |
| `trigger_summary` | 코드 스캔에서 발견된 문법임을 한 줄로 |
| `user_known` | `기초부터` -- 스캔 전제상 해당 문법을 모른다고 본다 |
| `discussion_context` | 스캔 대상·맥락 (어느 코드베이스를 왜 스캔했나) |
| `snippets` | 스캐너가 준 `usages`(코드 발췌 앵커) |
| `kind` | `code` (이 스킬은 항상) |
| `language` | 확정 언어 |

### triggered_by 값

이 스킬은 `code-scan` 하나만 쓴다. 스캔으로 발견된 문법은 사용자가 그것을 모른다는 전제이므로 writer 가 기초부터 깐다.

<PENETRATE>
이 스킬의 writer 입력은 `kind: code`, `triggered_by: code-scan`, `user_known: 기초부터` 로 채운다.
</PENETRATE>

## 비자명 문법 카탈로그

스캔은 언어별 카탈로그 `skills/knowledge-scan/languages/<lang>.md` 에 등재된 "정리할 만한 비자명 문법" 만 후보로 본다. 언어 기본기는 제외한다.

각 항목의 신호는 그 토픽을 고유하게 대표하는 강앵커로 정의한다. `&&`·`|` 같이 흔하고 모호한 토큰은 오탐만 늘리므로 신호로 쓰지 않는다.

새 언어를 지원하려면 `skills/knowledge-scan/languages/` 에 `<lang>.md` 를 더한다.
