# 논의 감시 캡처

활성된 동안 대화를 지켜보며 개념 공백을 자동 감지하고, 사용자의 명시 저장 요청도 함께 받아 wip 로 캡처하는 스킬.

wip 를 확정지식으로 올리는 승급은 별도 스킬 `knowledge-promote` 가 담당한다. 본 스킬은 캡처까지만 다룬다.

---

## 활성 조건

이 스킬은 세 방식으로 활성된다. 어느 쪽이든 활성 후 동작은 같다.

| 활성 방식 | 촉발 |
|------|------|
| 자동 활성 | SessionStart 훅(`hooks/session-skill-list.sh`)이 매 세션 이 overview 를 주입한다 |
| 명시 호출 | 사용자가 `/knowledge-capture` 슬래시 명령으로 부른다 |
| 자동 호출 | 사용자 발화가 SKILL.md 의 description 과 맞아 하네스가 이 스킬을 띄운다 |

<FORBIDDEN>
훅 주입이나 슬래시 명령, description 매칭 없이 이 스킬의 감시를 시작하지 않는다.
</FORBIDDEN>

---

## 하위 스킬

이 파일은 활성된 동안 매 발화에 쓰는 판정 규칙만 담는다. 캡처가 확정된 뒤의 절차는 아래 파일에 있고, 확정 시점에 Read 툴로 로드한다.

| 파일 | 역할 |
|------|------|
| `skills/knowledge-capture/delegate/delegate.md` | 캡처 확정 후 -- 경로 확보 · 기존 정리분 대조 · writer 위임 |
| `references/knowledge-repos.md` | 네 knowledge 스킬 공용 -- 경로 검증. delegate.md 가 로드를 지시한다 |
| `references/knowledge-wip-protocol.md` | wip 를 만드는 세 스킬 공용 -- writer 호출 · 저장 규칙. delegate.md 가 로드를 지시한다 |

에이전트는 `knowledge-writer` 하나를 쓴다. 정의 파일은 플러그인 루트 `agents/` 에 있다.

| 에이전트 | 파일 | 역할 |
|----------|------|------|
| `knowledge-writer` | `agents/knowledge-writer.md` | 메인의 입력을 받아 wip 본문을 작성하고 반환 (저장은 메인이 수행) |

## 두 갈래 트리거

캡처는 두 트리거로 시작된다. 둘은 활성된 동안 동시에 감시된다.

이 문서에서 "경로" 는 파일시스템 경로만 가리킨다. 캡처가 어느 쪽으로 들어왔는지는 "트리거" 로 쓴다.

| 트리거 | 촉발 | 대상 지식 |
|--------|------|----------|
| 자동 감지 | LLM 이 대화를 점수표로 판정해 발동 | 개념만 |
| 명시 요청 | 사용자가 저장을 직접 지시 | 개념 + 코드/문법(지명) |

코드/문법은 명시 요청으로만 들어오며, 코드베이스를 훑어 뽑는 일은 별도 스킬 `knowledge-scan` 이 담당한다.

---

## 실행 순서

1. 활성 (`활성 조건` 의 세 방식 중 하나)
2. 매 발화마다 두 트리거를 동시 감시한다 (`자동 감지 점수표` / `사용자 명시 지시 트리거`)
3. 캡처가 확정되면 `skills/knowledge-capture/delegate/delegate.md` 를 Read 툴로 로드하고 그 절차를 따른다 -- 경로 확보, 기존 정리분 대조, `knowledge-writer` 위임까지가 그 파일 소관이다

### 단계 시각화 (TaskCreate)

매 발화를 task 로 만들지 않는다. 임계 도달이나 명시 요청으로 writer 위임이 발생하는 시점만 표시한다 -- 백그라운드 에이전트 호출이므로 호출 즉시 completed 로 닫고, subject 는 "knowledge-writer 에이전트 호출" 형식으로 쓴다.

---

## 자동 감지 점수표

활성된 동안 메인 LLM 은 매 발화마다 개념 지식(패턴·아키텍처·라이브러리)에 한해 점수표를 적용해 자동 감지를 수행한다.

<FORBIDDEN>
코드/문법 지식을 점수표로 자동 감지하지 않는다.
</FORBIDDEN>

점수표는 그룹별로 나뉜다. 각 행은 점수 외에 역할 태그와 드러나는 `user_known` 을 갖는다. 역할 태그로 "발동 판정(게이트)" 과 "깊이 보정(user_known)" 을 한 표에서 갈라 뽑는다 (아래 `역할 태그와 추출` 참조).

### 공백 (개념 부재 신호)

| # | 기준 | 점수 | 역할 | 드러나는 user_known | 예시 |
|---|---|---|---|---|---|
| A1 | 처음 등장하는 개념이고 wiki 캐시에 미존재 | +1 | gate | - | RUDP 가 갑자기 언급됨 |
| A2 | 해당 개념 없이 현재 논의 판단 자체가 불가 | +2 | gate | - | RUDP 설계인데 UDP 를 모르면 진행 불가 |
| A3 | 이름조차 생소한 개념을 "모른다 / 뭐지?" 로 자기보고 | +2 | both | 그 개념 자체를 모름 | "zmq 가 뭐지? 처음 들어봐" |
| A4 | 이름은 익숙한데(들어봤다·써봤다) 용도·역할을 말하지 못함 | +1 | user_known | 이름만 알고 용도 모름 | "RUDP 들어는 봤는데 뭐 하는진 모름" |

### 오해 (잘못 아는 신호)

| # | 기준 | 점수 | 역할 | 드러나는 user_known | 예시 |
|---|---|---|---|---|---|
| M1 | 두 개념을 (환원 선언 없이) 용어로 구분 없이 섞어 씀 | +2 | both | 두 개념의 경계를 모름 | "패킷" 과 "세그먼트" 를 같은 의미로 |
| M2 | "항상 / 절대" 같은 절대화로 단정 | +2 | both | 예외·조건을 모름 | "락은 항상 느리다" |
| M3 | 옛 버전 정의를 현재 사실로 단정 | +2 | both | 버전에 따라 바뀐 걸 모름 | "view 는 항상 비소유" (DR 로 깨짐) |

오해는 종류만 행으로 두고, 반복은 가산으로 더한다. M1/M2/M3 중 한 행에 해당하는 같은 오해가 2회 이상 반복되면 그 행 점수에 +1 한다.

### 앵커 (잘못된 기준점 신호)

| # | 기준 | 점수 | 역할 | 드러나는 user_known | 예시 |
|---|---|---|---|---|---|
| C1 | (개념 동일시가 아니라) 화제가 인접 계층으로 반복 이탈 | +2 | both | 경계 인접 개념과 혼동 | UDP 논의 중 계속 IP 계층으로 빠짐 |
| C2 | "결국 ~같은 거" 식 명시적 환원·동일시 선언 | +2 | both | 친숙 개념으로 잘못 동일시 | "코루틴? 결국 스레드 같은 거잖아" |
| C3 | 하위 요소를 전체로 착각 | +1 | user_known | 부분-전체 관계 오인 | "views 가 곧 Ranges" |

M1·C1·C2 는 겹치기 쉬우니 행위로 가른다: 명시적 "결국 ~같은 거" 환원 선언이면 C2, 선언 없이 용어를 섞으면 M1, 동일시가 아니라 화제가 다른 계층으로 흐르면 C1. 한 발화는 셋 중 하나로만 친다.

A1 은 wiki 캐시가 정의돼 있을 때만 적용한다. wiki 가 없으면 A1 자체를 점수 계산에서 뺀다.

### 역할 태그와 추출

각 행의 역할 태그는 해당한 행의 내역을 두 군데로 갈라 쓰기 위한 것이다.

- `gate` -- 발동 판정(점수 합산)에만 기여. 깊이엔 쓰지 않는다
- `user_known` -- 깊이 보정에만 기여. 발동 점수에도 합산되지만, 주 용도는 writer 출발 수준 신호다
- `both` -- 발동·깊이 양쪽에 기여

발동 판정(게이트): 해당하는 모든 행의 점수를 합산해 임계 이상이면 발동한다. 어느 한 행에 해당한다고 점수와 무관하게 즉시 발동하지 않는다(단독 발동 룰 없음).

`user_known` 구성(깊이 보정): 해당하는 행 중 `user_known`·`both` 태그 행만 추려, 그 "드러나는 user_known" 을 모아 writer 입력 `user_known` 을 구성한다. `gate` 행은 깊이에 넣지 않는다.

해당하는 행이 전부 `gate` 면 `user_known` 이 빈다. A1 + A2 가 그 조합이다. 이때는 `그 개념 자체를 모름` 을 기본값으로 채워 writer 를 부른다. 되묻기는 명시 요청 트리거에만 둔다 (delegate.md `user_known 보충 되묻기`).

<FORBIDDEN>
자동 감지로 발동한 캡처에서 `user_known` 을 보충하려고 사용자에게 되묻지 않는다.
</FORBIDDEN>

### 행 판정 우선순위

행마다 판정 난이도가 다르다. 아래 순서로 본다.

- A3 · C2 · M2 를 먼저 본다. 셋은 사용자 말에 글자로 드러나므로(자기보고 "모른다", "결국 ~같은 거", "항상 / 절대") LLM 자기지식 없이 판정된다.
- M1 · M3 는 LLM 이 그 주제의 정답을 알 때만 판정한다. 오해를 감지하려면 무엇이 맞는지 알아야 하기 때문이다.
- 나머지 행은 위 판정을 마친 뒤 보탠다.

<FORBIDDEN>
LLM 이 정답을 모르는 주제에서 M1 · M3 를 추측으로 판정하지 않는다.
</FORBIDDEN>

### 임계값

| 합계 점수 | 동작 |
|----------|------|
| 3점 미만 | 무시 |
| 3점 이상 | 캡처 확정. `delegate/delegate.md` 를 로드해 위임 절차로 넘어간다 |

<FORBIDDEN>
현재 작업과 직접 연관 없는 주제는 점수 계산 대상으로 삼지 않는다.
</FORBIDDEN>

## 사용자 명시 지시 트리거

사용자가 특정 주제에 대해 knowledge 저장을 직접 요청한 경우 즉시 위임한다.
이 트리거는 대화 중 "이거 남겨줘" 류의 지시다. 코드베이스를 훑어 문법을 뽑는 명령은 `knowledge-scan` 스킬 소관이다.

### 인정 발화 패턴

저장 의도가 드러난 발화는 모두 명시 지시로 인정한다.

- "이거 knowledge 로 남겨줘"
- "이 부분 wip 로 저장해줘"
- "이 정보 기억해둬" (knowledge 맥락)
- 기타 사용자가 명시적으로 저장 의도를 표한 표현

<FORBIDDEN>
명시 지시 발화를 "점수 3점 미만이라 무시" 로 처리하지 않는다.
</FORBIDDEN>

확정 후 절차(`triggered_by` 값, 수준 보충 되묻기 등)는 delegate.md `명시 요청 트리거의 추가 절차` 에 있다.

## 점수 계산 주체와 휘발성

- 점수표 비교와 누적 계산은 메인 LLM 의 작업이다.
- 점수표 · 누적값은 메인 LLM 컨텍스트 안에만 존재하며, 세션 종료 · 컴팩 시 초기화된다 (세션 단위 휘발).

<FORBIDDEN>
점수표 자체나 누적 점수를 별도 파일 · 인덱스에 저장하지 않는다.
</FORBIDDEN>

---

## 누적 규칙

- 점수는 세션 내에서만 유효하다. 세션이 바뀌면 모든 주제 점수 리셋.
- 다른 주제는 독립적으로 점수 계산한다.
- 사용자가 이미 알고 있다고 명시한 주제는 해당 세션의 점수 계산 · 위임 대상에서 제외한다 (세션이 바뀌면 다시 적용).
- 여러 주제가 동시에 임계를 넘는 경우 모두 위임 대상에 포함한다 (하나만 선택하지 않는다).
- 임계를 넘어 `knowledge-writer` 로 위임된 주제는 해당 세션에서 추가 점수 누적 및 중복 위임 대상에서 제외한다 (한 번 위임되면 그 세션 동안 고정).
- delegate.md `기존 정리분 대조` 에서 중복으로 판정돼 건너뛴 주제도 위임된 것과 동일하게 해당 세션의 추가 점수 누적 · 위임 대상에서 제외한다.
- 위 두 규칙은 세션 안에서만 유효하다. 세션을 넘는 중복은 delegate.md `기존 정리분 대조` 가 담당한다.
- wiki 가 정의돼 있으면, 거기 등재된 주제는 점수 계산 대상에서 제외한다 (요약 비교로 의미적 중복 판단). wiki 가 없으면 세션 밖 중복 방지는 delegate.md `기존 정리분 대조` 가 전담한다.
