# 캡처 확정 후 위임 절차

캡처가 확정된 뒤 실행하는 절차. 아래 절 순서대로 진행한다.

---

## 공용 프로토콜

공용 파일 둘이 각각 단일 출처다.

| 파일 | 담는 것 |
|------|--------|
| `references/knowledge-repos.md` | 받은 경로가 등록된 지식 저장소인지 판정하는 절차 |
| `references/knowledge-wip-protocol.md` | `knowledge-writer` 호출 형태 · 입력 포맷 · 반환 본문 저장 |

둘 다 Read 툴로 로드해 따른다. 본 스킬이 받는 경로는 wip 저장 디렉토리 하나이며, 경로 검증 절차를 그 경로에 적용한다.

### 저장 경로 확보

물을지 말지는 지금 검증된 경로를 알고 있는가로 가른다. 모르면 입력받아 검증한다.

캡처가 확정되지 않은 상태에서 wip 저장 경로를 미리 묻지 않는다.
</FORBIDDEN>

<FORBIDDEN>
검증된 wip 저장 경로를 알고 있는 상태에서 경로를 다시 묻지 않는다.
</FORBIDDEN>

## 기존 정리분 대조

대조 시점은 경로를 확보한 뒤 writer 를 호출하기 전이다.

### 대조 방법

- wip 디렉토리와 확정지식 디렉토리를 Glob 해 파일명 목록을 얻는다. 확정지식 디렉토리는 wip 경로가 속한 저장소 루트의 `knowledge/` 다.
- 파일명 목록과 이번 `topic` 을 문자열 일치가 아니라 같은 주제인지로 판단한다.
- 파일명만으로 판단이 서지 않으면 후보 파일을 Read 해 확인한다.

### 판정 후 동작

중복으로 판정되면 어느 트리거로 들어왔는지에 따라 갈린다.

| 트리거 | 동작 |
|--------|------|
| 자동 감지 | writer 를 호출하지 않고 건너뛴다. 어느 파일과 겹쳐 건너뛰었는지 한 줄만 알린다 |
| 명시 요청 | 겹치는 파일을 제시하고 보강할지 새로 쓸지 묻는다 |

보강을 택하면 `triggered_by` 를 `user-request-reinforce` 로 보내고 기존 파일의 절대경로를 `discussion_context` 에 함께 적는다. 새로 쓰기를 택하면 `user-request` 그대로다. 어느 쪽이든 기존 파일을 덮어쓰지 않고 번호를 더한 파일을 만든다.

<FORBIDDEN>
자동 감지로 발동한 캡처가 중복으로 판정되면 보강 여부를 사용자에게 묻지 않는다.
</FORBIDDEN>

## 명시 요청 트리거의 추가 절차

overview `사용자 명시 지시 트리거` 로 들어온 캡처에만 적용한다.

### 처리 규칙

- 호출 형식은 자동 감지 트리거와 동일하다 (공용 프로토콜의 `knowledge-writer 호출`)
- `triggered_by` 필드에 점수표 코드 대신 `user-request` 를 적는다
- `trigger_summary` 에 어떤 발화로 지시가 발생했는지 한 줄 기술한다
- 동일 세션 내 같은 주제 중복 위임 방지 규칙을 동일 적용한다
- writer 호출 전에 `user_known` 이 비었거나 한두 항목뿐이면 수준 보충 질문을 한다 (아래 `user_known 보충 되묻기`)

### user_known 보충 되묻기

- 되묻기는 `user_known` 이 비었거나 한두 항목뿐일 때만 한다. 요청에 수준이 이미 드러나면(사용자가 인접 지식·목적을 이미 말함) 생략한다.
- probe 2종을 쓴다.
  - 인접 지식 probe: "관련된 X 는 아시나요?" (예: UDP 면 TCP) -- 출발 수준을 잡는다.
  - 목적 probe: "왜·어디에 쓰려고 남기나요?" -- 목적이 깊이를 정한다.
- 받은 답을 `user_known` 과 `discussion_context` 에 실어 writer 를 호출한다.
- "모른다" 는 답도 "그 개념 자체를 모름" 신호로 `user_known` 에 실어 writer 가 기초부터 다루게 한다(A3 와 같은 취지). 사용자가 응답하지 않으면 `user_known` 을 빈 채로 두고 그대로 writer 를 호출한다 -- 캡처 확정이 우선이다.

<FORBIDDEN>
수준 보충 probe 를 두 번 이상 반복하지 않는다.
</FORBIDDEN>

## 위임 실행

개념(무엇·왜)과 코드 사용법(어떻게)이 한데 섞인 주제는 concept wip 와 code wip 두 개로 나눠 캡처한다(kind 가 다르면 다른 wip -- `skills/knowledge-promote/format/format.md` 의 `kind 결정 규칙` 참조).

이 자동 위임은 wip 단계에 한정된다. wip -> 확정지식 승급 단계는 별도 사용자 확인 규약을 따른다.

캡처 과정에서 사용자에게 묻는 나머지는 아래 금지에 해당하지 않는다 -- 경로를 모를 때의 저장 경로 입력(`저장 경로 확보`), `user_known` 이 빌 때의 수준 보충 질문, 기존 정리분과 겹칠 때의 보강 여부 질문(`기존 정리분 대조`)이다.

<FORBIDDEN>
wip 단계에서 위임 여부 · 묶음 · 분리 여부를 사용자에게 묻지 않는다.
</FORBIDDEN>

## writer 위임

호출 형태·입력 포맷·저장 책임은 공용 프로토콜의 `knowledge-writer 호출` 과 `반환 본문 저장` 을 그대로 따른다. 이 스킬이 채우는 입력값은 다음과 같다.

| 필드 | 이 스킬의 값 |
|------|-------------|
| `save_path` | `저장 경로 확보` 에서 확보한 저장 경로 |
| `sections_path` | 플러그인 루트 `references/knowledge-wip-sections.md` 의 절대경로 |
| `topic` | 주제 식별자 (kebab-case). 메인이 정한다 |
| `triggered_by` | 아래 `triggered_by 값` |
| `trigger_summary` | 어떤 발화·판정으로 발동했는지 한 줄 |
| `user_known` | 자동 감지는 해당하는 `user_known`·`both` 행에서. 해당하는 행이 전부 `gate` 면 `그 개념 자체를 모름`. 명시 요청은 보충 probe 답에서 |
| `discussion_context` | 캡처가 발생한 논의 맥락. 보강이면 기존 파일의 절대경로도 함께 (`기존 정리분 대조`) |
| `snippets` | 대화 발췌 |
| `kind` | `concept` 기본. 사용자가 코드/문법을 지명했으면 `code` |
| `language` | `kind: code` 일 때만 |

### triggered_by 값

이 스킬의 `triggered_by` 는 점수표 코드 또는 명시 요청 코드다. 복수 가능하다.

| 값 | 뜻 |
|----|-----|
| `A1` ~ `A4` | 공백 그룹에서 해당한 행 |
| `M1` ~ `M3` | 오해 그룹에서 해당한 행 |
| `C1` ~ `C3` | 앵커 그룹에서 해당한 행 |
| `user-request` | 사용자 명시 저장 요청 (점수표 우회) |
| `user-request-reinforce` | 명시 요청인데 기존 정리분과 겹쳐 사용자가 보강을 택함. 기존 노트를 읽고 빠진 부분 위주로 쓴다 |
