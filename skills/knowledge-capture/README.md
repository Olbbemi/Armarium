# knowledge-capture

논의에 필요한 지식을 대화에서 감지·수집해 wip 초안으로 누적하는 스킬.

## 무엇을 하나

활성된 동안 대화를 지켜보며 지식 부재를 자동 감지하거나, 사용자의 명시 저장 요청을 받아 캡처한다.<br>
캡처가 확정되면 `knowledge-writer` 에이전트에 wip 본문 작성을 위임한다.<br>
wip 누적까지만 담당하며, 확정지식 승급은 별도 스킬 [`knowledge-promote`](../knowledge-promote/README.md)가 맡는다.

## 형제 스킬

wip 를 만드는 스킬은 셋이고, 진입 경로가 서로 다르다. 저장 경로 검증 · writer 호출 · 저장 규칙은 [`references/knowledge-wip-protocol.md`](../../references/knowledge-wip-protocol.md) 를 셋이 공유한다.

| 스킬 | 진입 | 앵커 |
|------|------|------|
| `knowledge-capture` | 대화 중 감지 또는 명시 요청 (상시) | 대화 발췌 |
| [`knowledge-scan`](../knowledge-scan/README.md) | 코드베이스 스캔 명령 (단발) | 코드 발췌 |
| [`knowledge-study`](../knowledge-study/README.md) | CS 로드맵에서 주제 선택 (단발) | 카탈로그 항목 |

## 언제 쓰나

**매 세션 자동 활성**된다. SessionStart 훅(`hooks/session-skill-list.sh`)이 이 스킬의 overview 를 컨텍스트에 실어 보내므로, 슬래시 명령 없이도 활성 상태로 시작한다. `/knowledge-capture` 로 직접 부를 수도 있다.<br>
자동 활성은 이 스킬만의 예외다. 논의 중 지식 부재는 사용자가 스킬을 부를 생각을 못 하는 순간에 드러나므로, 명시 호출에만 의존하면 잡을 시점을 놓친다.<br>
훅 주입도 슬래시 명령도 없는 세션에서 LLM 이 스스로 켜지는 않는다.

## 저장 경로는 나중에 묻는다

경로는 활성 시점이 아니라 **첫 캡처가 확정되는 순간**에 처음 묻는다. 자동 활성이 기본이라 활성 시점에 물으면 knowledge 와 무관한 세션까지 전부 경로 질문으로 시작하기 때문이다.<br>
한 번 확정한 경로는 그 세션 동안 재사용하고, 캡처가 없는 세션은 아예 묻지 않는다.

## 두 갈래 트리거

| 트리거 | 촉발 | 대상 지식 |
|--------|------|----------|
| 자동 감지 | LLM 이 대화를 점수로 자동 발동 | 개념만 |
| 명시 요청 | 사용자가 저장을 직접 지시 | 개념 + 코드/문법(지명) |

코드/문법 지식은 자동 감지가 잡지 않는다 -- 눈앞에 코드가 있어야 물어볼 수 있어서다. 그래서 명시 요청으로만 들어오고, 코드베이스를 훑어 뽑는 경로는 `knowledge-scan` 이 담당한다.

## 이미 정리한 주제는 다시 안 만든다

세션 점수는 세션이 끝나면 리셋되므로, 상시 활성만으로는 어제 캡처한 주제를 오늘 또 캡처한다. 그래서 경로를 확보한 뒤 writer 를 부르기 전에 `wip/` 와 `knowledge/` 파일명을 Glob 해 대조한다.<br>
`topic` 은 메인이 그때그때 정해 같은 개념이 다른 슬러그로 나오므로(`lock-contention` 과 `mutex-contention`), 문자열 일치가 아니라 같은 주제인지로 판단한다.

| 트리거 | 중복일 때 |
|--------|----------|
| 자동 감지 | 건너뛴다. 어느 파일과 겹쳤는지 한 줄만 알린다 |
| 명시 요청 | 겹치는 파일을 보여주고 보강할지 새로 쓸지 묻는다 |

자동 감지에서 묻지 않는 이유는 사용자가 시킨 적 없는 발동이어서다. 어느 쪽이든 기존 파일을 덮어쓰지 않고 suffix 파일을 만들며, 병합은 승급 단계 소관이다.

## 구조

- `overview.md` -- 진입점. 활성 조건, 두 트리거, 점수표, 기존 정리분 대조, writer 위임 전부
- `knowledge-writer` 에이전트 (플러그인 루트 `agents/knowledge-writer.md`) -- 메인 입력을 받아 외부 조사 + wip 본문 작성 후 반환 (저장은 안 함)

## 자동 감지 점수표

개념 지식만 자동 감지한다. 점수표는 세 그룹으로 나뉘고, 각 행에 역할 태그(`gate`/`user_known`/`both`)가 붙어 발동 판정과 깊이 보정을 한 표에서 갈라 뽑는다.

- **공백** (A1~A4) -- 처음 등장·판단 불가·자기보고 "모른다"·이름만 앎
- **오해** (M1~M3) -- 개념 혼용·절대화·옛 정의를 사실로 (같은 오해 2회 반복 시 해당 행 +1 가산)
- **앵커** (C1~C3) -- 인접 계층 이탈·친숙 개념 환원·하위를 전체로 착각

켜진 행 점수 합계가 **3점 이상**(임계 3~4)이면 즉시 위임, 미만은 무시. 점수는 메인 LLM 컨텍스트에만 존재하며 세션 단위로 휘발(파일 저장 안 함).<br>
켜진 행이 전부 `gate` 면(A1 + A2) `user_known` 이 비는데, 되묻지 않고 "그 개념 자체를 모름" 을 기본값으로 채운다. 자동 감지는 사용자를 붙잡지 않는다.

행마다 판정 난이도가 달라 순서가 있다. A3 · C2 · M2 는 사용자 말에 글자로 드러나 LLM 자기지식 없이 판정되므로 먼저 본다. M1 · M3 는 오해 감지라 LLM 이 그 주제의 정답을 알 때만 켜고, 모르는 주제에서 추측으로 켜지 않는다.

어느 행이 실제로 켜져 노트가 만들어졌는지는 wip 첫 줄 `wip-meta` 주석의 `triggered_by` 로 남는다.

## 입력 / 출력

- **저장 위치** -- 첫 캡처 확정 시 사용자에게 입력받는 디렉토리 하위 `<저장경로>/<topic>.md`. 입력 경로는 origin remote 가 `git@github.com:Olbbemi/Herbarium.git` 인 Herbarium 저장소 하위여야 하며, 아니면 다시 입력받는다
- **writer 입력 포맷** -- `save_path` / `topic` / `triggered_by`(점수표 코드, `user-request`, 또는 보강이면 `user-request-reinforce`) / `trigger_summary` / `user_known` / `discussion_context` / `snippets` / `kind` / `language` (라벨+콜론 구조화 텍스트, JSON 아님)

## 주의

- 훅 주입도 슬래시 명령도 없는 세션에서 LLM 자가판단으로 활성·점수 계산을 시작하지 않는다.
- 캡처가 확정되지 않은 상태에서 저장 경로를 미리 묻지 않는다.
- writer 를 부르기 전에 기존 wip · 확정지식 파일명과 이번 topic 을 대조한다.
- 자동 감지로 발동한 캡처가 중복으로 판정되면 보강 여부를 사용자에게 묻지 않는다.
- 백그라운드 writer 에게 wip 파일을 직접 저장(Write/Edit)시키지 않는다. 저장은 메인이 한다.
- wip 단계에서는 위임·묶음·분리 여부를 사용자에게 묻지 않고 자동 진행한다 (승급 단계는 별도 승인 규약). 단 명시 요청 경로에서 `user_known` 이 비면 writer 호출 전에 수준 보충 질문은 한다.
