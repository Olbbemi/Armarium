# knowledge-capture

논의에 필요한 지식과 코드베이스에 쓰인 문법 지식을 감지·수집해 wip 초안으로 누적하는 스킬.

## 무엇을 하나

두 모드로 동작한다. 논의 감시형은 활성된 동안 대화를 지켜보며 지식 부재를 자동 감지하거나 사용자의 명시 저장 요청을 캡처하고, 코드 스캔형은 사용자의 명시 명령으로 코드베이스를 훑어 비자명 문법을 후보로 뽑아 캡처한다.<br>
두 모드 모두 `knowledge-writer` 에이전트에 wip 본문 작성을 위임한다.<br>
wip 누적까지만 담당하며, 확정지식 승급은 별도 스킬 [`knowledge-promote`](../knowledge-promote/README.md)가 맡는다.

## 언제 쓰나

`/knowledge-capture` 슬래시 명령으로 **명시적으로 활성**했을 때만 동작한다.<br>
활성 판단은 사용자에게만 있고, LLM 자가판단으로 활성하지 않는다.<br>
활성 후 논의 감시(모드 1)는 상시 돌고, 코드 스캔(모드 2)은 사용자가 스캔을 명시 명령할 때만 돈다.

## 모드와 트리거

모드는 2개지만, 캡처가 시작되는 트리거로 보면 모드 1 이 두 갈래로 갈려 총 3개다.

| 모드 | 트리거 | 촉발 | 대상 지식 |
|------|--------|------|----------|
| 1 논의 감시 | 1-a 자동 감지 | LLM 이 대화를 점수로 자동 발동 | 개념만 |
| 1 논의 감시 | 1-b 명시 요청 | 사용자가 저장을 직접 지시 | 개념 + 코드/문법(지명) |
| 2 코드 스캔 | 2 스캔 | 사용자가 스캔을 명시 명령 | 코드/문법(코드베이스에서 발견) |

코드/문법 지식은 자동 감지(1-a)가 잡지 않는다 -- 눈앞에 코드가 있어야 물어볼 수 있어서다. 그래서 1-b(지명)나 2(스캔)로만 들어온다.

## 구조

- `overview.md` — 진입점. 공유 기반(저장 경로 · `knowledge-writer` 호출 · 반환 처리)와 모드 분기 정의
- `modes/conversation.md` — 모드 1(논의 감시): 점수표 · 명시 요청 트리거
- `modes/code-scan.md` — 모드 2(코드 스캔): 발동 규칙 · 언어 판정 · 스캐너 호출 · 후보 게이트
- `languages/<lang>.md` — 언어별 비자명 문법 카탈로그 (현재 `cpp.md`)
- `knowledge-code-scanner` 에이전트 (플러그인 루트 `agents/knowledge-code-scanner.md`) — 코드베이스 순회 + 문법 탐지 + 후보 반환 (모드 2)
- `knowledge-writer` 에이전트 (플러그인 루트 `agents/knowledge-writer.md`) — 메인 입력을 받아 외부 조사 + wip 본문 작성 후 반환 (저장은 안 함, 두 모드 공용)

## 동작 흐름

### 공통

- 활성 직후 저장 경로를 사용자에게 입력받고 git origin remote 로 Herbarium 여부를 검증한다.
- 캡처가 확정되면 `knowledge-writer` 를 **백그라운드**(Task, `run_in_background: true`)로 호출하고, writer 가 최종 메시지로 반환한 본문을 메인이 wip 파일로 저장한다(HTML 엔티티 원복).
- writer 는 파일을 저장하지 않는다.

### 모드 1 — 논의 감시

1. 매 발화마다 두 트리거 동시 감시
   - **1-a 자동 감지** — 점수표 합계 3점 이상 (개념 지식만)
   - **1-b 명시 요청** — 사용자의 직접 저장 요청 ("이거 knowledge로 남겨줘" 등)
2. 트리거 발생 시 호출 입력을 구성해 writer 에 위임

### 모드 2 — 코드 스캔

1. 스캔 명시 명령 인식 (자연어, 오발동 방지 3단 규칙 -- 뚜렷하면 즉시 / 모호하면 한 줄 확인 / 의도 없으면 무시)
2. 스캔 대상 경로 확보(항상 명시) + 언어 판정 (확장자 감지 -> 카탈로그 교차 -> 사용자 확인)
3. `knowledge-code-scanner` 를 **포그라운드**로 호출 -> 후보 목록(`topic` / `usages` / `why`) 반환
4. 후보 게이트 — 사용자가 캡처할 topic 을 고른다 (스캔 모드의 유일한 질문)
5. 고른 topic 마다 writer 에 위임

### 진행 시각화 (TaskCreate)

실행 단계가 드러나는 모드 2(코드 스캔)는 진행을 TaskCreate 로 시각화한다(포그라운드 단계 in_progress -> completed, 백그라운드 에이전트 호출은 즉시 completed, 후보 게이트는 확인 직전 completed).<br>
모드 1(논의 감시)은 상시 배후 감지라 매 발화를 task 로 만들지 않고, 임계 도달로 writer 위임이 발생하는 시점만 표시한다.

## 자동 감지 점수표 (모드 1-a)

개념 지식만 자동 감지한다(코드/문법은 명시 요청이나 스캔으로만 캡처). 점수표는 세 그룹으로 나뉘고, 각 행에 역할 태그(`gate`/`user_known`/`both`)가 붙어 발동 판정과 깊이 보정을 한 표에서 갈라 뽑는다.

- **공백** (A1~A4) — 처음 등장·판단 불가·자기보고 "모른다"·이름만 앎
- **오해** (M1~M3) — 개념 혼용·절대화·옛 정의를 사실로 (같은 오해 2회 반복 시 해당 행 +1 가산)
- **앵커** (C1~C3) — 인접 계층 이탈·친숙 개념 환원·하위를 전체로 착각

켜진 행 점수 합계가 **3점 이상**(임계 3~4)이면 즉시 위임, 미만은 무시. 점수는 메인 LLM 컨텍스트에만 존재하며 세션 단위로 휘발(파일 저장 안 함). 상세 표(점수·역할 태그·드러나는 user_known)는 `modes/conversation.md` 참조.

## 비자명 문법 카탈로그 (모드 2)

스캔은 언어별 카탈로그 `languages/<lang>.md` 에 등재된 "정리할 만한 비자명 문법" 만 후보로 본다(언어 기본기는 제외). 각 항목의 신호는 그 토픽을 고유하게 대표하는 **강앵커**로 정의하며, `&&`·`|` 같이 흔하고 모호한 토큰은 오탐만 늘리므로 신호로 쓰지 않는다.<br>
스캐너는 강앵커를 Grep 으로 찾고 Read 로 확증하며, 기존 knowledge/wip 파일명과 겹치는 topic 은 걸러낸다(dedup). 새 언어는 `languages/` 에 `<lang>.md` 를 더하면 된다.

## 입력 / 출력

- **저장 위치** — 활성 시 사용자에게 입력받는 디렉토리 하위 `<저장경로>/<topic>.md`. 입력 경로는 origin remote 가 `git@github.com:Olbbemi/Herbarium.git` 인 Herbarium 저장소 하위여야 하며, 아니면 다시 입력받는다
- **스캔 대상 경로** (모드 2) — 저장 경로와 별개로, 스캔할 코드베이스 경로를 항상 명시적으로 확보한다 (명령에 있으면 그것, 없으면 물어 받음)
- **writer 입력 포맷** — `save_path` / `topic` / `triggered_by`(모드 2 는 `code-scan`) / `trigger_summary` / `user_known`(모드 2 는 "기초부터") / `discussion_context` / `snippets`(모드 2 는 코드 발췌) / `kind`(모드 2 는 항상 `code`) / `language` (라벨+콜론 구조화 텍스트, JSON 아님)

## 주의

- LLM 자가판단으로 활성·점수 계산·스캔을 시작하지 않는다. 스캔은 사용자의 명시 명령 전용이다.
- 스캔 모드는 후보 게이트에서 사용자가 고른 topic 만 캡처한다. 고르지 않은 후보·"카탈로그 보강 후보" 를 임의로 캡처하지 않는다.
- 백그라운드 writer·스캐너에게 wip 파일을 직접 저장(Write/Edit)시키지 않는다. 저장은 메인이 한다.
- wip 단계에서는 위임·묶음·분리 여부를 사용자에게 묻지 않고 자동 진행한다 (승급 단계는 별도 승인 규약). 단 명시 요청 경로에서 `user_known` 이 비면 writer 호출 전에 수준 보충 질문은 한다.
