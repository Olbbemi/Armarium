# 모드 2: 코드 스캔형 캡처

사용자의 명시 명령으로 대상 코드베이스를 훑어, 쓰인 비자명 문법을 후보로 뽑고 사용자가 골라 wip 로 캡처하는 모드.
저장 경로 설정 · `knowledge-writer` 호출 형태 · 입력 포맷 · 반환 원복 같은 **공유 기반은 overview.md** 에 있고, 이 파일은 이 모드 고유의 발동·대상 판정·스캐너 호출·후보 게이트만 다룬다.

이 모드는 사용자가 스캔을 명시적으로 명령했을 때만 돈다. 모드 1(논의 감시)과 충돌하지 않고 공존한다.

---

## 발동 규칙

스캔은 사용자가 코드베이스 스캔을 **명시적으로 명령했을 때만** 발동한다. 발동 신호는 자연어 발화로 인식하며, 별도 문법·인자를 요구하지 않는다.

<RICOCHET>
LLM 자가판단으로 스캔을 발동하지 않는다. 사용자의 명시 스캔 명령 없이는 돌지 않는다.
</RICOCHET>

### 진짜 스캔 명령의 3요소

한 발화가 스캔 명령인지는 아래 세 요소가 뚜렷이 모였는지로 가른다.

| 요소 | 뜻 | 아닌 예 |
|------|----|--------|
| 동작 | 훑기 / 스캔 / 조사 (쓸어보라는 의도) | "이 코드 봐줘 / 설명해줘 / 리뷰해줘" |
| 대상 | 코드베이스 / 디렉토리 / 코드 전반 | 대화 속 스니펫 하나 |
| 목적 | 쓰인 문법·기능을 뽑아 정리·캡처 | 버그 찾기 / 성능 분석 |

### 3단 처리

- **3요소가 다 뚜렷** ("이 코드베이스 문법 스캔해줘", "여기 쓰인 비자명 문법 뽑아줘") -- 확인 없이 발동한다. 이미 명시적이라 되묻는 것은 군더더기다.
- **일부만 있거나 모호** ("이 코드 좀 봐줘", "여기 뭐 쓰였나 볼까") -- 한 줄로 확인한 뒤에만 발동한다 ("코드베이스 문법 스캔을 돌릴까요?").
- **스캔 의도가 없음** (설명·리뷰·특정 함수 질문) -- 무시한다. 모드 1 은 그대로 지속된다.

<RICOCHET>
일반 대화의 코드 언급만으로 스캔을 자동 발동하지 않는다. 스캔 의도가 모호한데 확인 없이 발동하지 않는다.
</RICOCHET>

<PENETRATE>
스캔 의도가 모호하면 한 줄로 확인한 뒤에만 발동한다.
</PENETRATE>

---

## 스캔 대상 경로

스캔할 코드베이스 경로는 **항상 명시적으로 확보한다**. 현재 작업 디렉토리가 곧 소스라고 가정하지 않는다 -- 저장 경로를 활성 시 입력받는 것과 같은 취지다.

- 스캔 명령에 대상 경로가 담겼으면("src/ 스캔해줘") 그 경로를 쓴다.
- 담기지 않았으면("이 코드베이스 스캔해줘") 대상 경로를 한 줄 물어 받는다. 이는 확인 게이트가 아니라 필수 입력 수집이므로, 발동 규칙의 즉시 발동과 충돌하지 않는다.

이 경로가 스캐너 입력 `codebase_path` 가 된다. 저장 경로(Herbarium wip)와는 별개다.

<PENETRATE>
스캔 대상 경로를 명시적으로 확보한 뒤에 스캐너를 호출한다. 명령에 없으면 물어 받는다.
</PENETRATE>

## 언어 판정

스캐너는 언어별 카탈로그(`languages/<lang>.md`)를 기준으로 돌기 때문에, 대상의 언어를 먼저 정한다.

### 절차

1. 대상 경로의 파일 확장자를 훑어 어떤 언어들이 있는지 감지한다.
2. 감지된 언어를 보유 카탈로그(`languages/` 하위 `<lang>.md` 존재분)와 교차한다.
3. 감지 결과를 사용자에게 확인받은 뒤 스캔 언어를 확정한다.

### 확인 방식

- **카탈로그 보유 언어 하나** -- "이 코드베이스는 <lang> 인 것 같은데, 이걸로 스캔할까요?" 로 확인한다.
- **카탈로그 보유 언어 여럿** -- "이 코드베이스에 <lang1>, <lang2> 가 보이는데, 전부 스캔할까요, 일부만 할까요?" 로 확인한다.
- **카탈로그 없는 언어가 섞임** -- 그 언어는 카탈로그가 없어 스캔할 수 없음을 함께 알린다. 카탈로그 있는 언어만 대상이 된다.
- **카탈로그 보유 언어가 하나도 없음** -- "스캔 가능한 언어(카탈로그 보유)가 없습니다" 를 알리고 스캔을 중단한다.

사용자가 특정 언어를 콕 집어 명령했으면(그 언어 카탈로그가 있으면) 감지보다 그 지정을 우선한다.

확정된 언어마다 그 언어의 `languages/<lang>.md` 절대경로가 스캐너 입력 `catalog_path` 가 된다. 언어가 여럿이면 언어당 스캐너를 각각 호출한다.

<PENETRATE>
감지한 언어는 사용자에게 확인받은 뒤 스캔 언어로 확정한다.
</PENETRATE>

<RICOCHET>
카탈로그가 없는 언어를 스캔 대상으로 삼지 않는다.
</RICOCHET>

## 스캐너 호출

언어가 확정되면 언어마다 `knowledge-code-scanner` 에이전트를 호출해 후보 목록을 받는다.

### 호출 형태

| 항목 | 값 |
|------|----|
| 호출 도구 | Task |
| `subagent_type` | `knowledge-code-scanner` |
| `run_in_background` | `false` (포그라운드) |
| 스캐너 출력 | 후보 목록을 최종 메시지로 반환 (파일 저장 안 함) |

스캐너 호출은 **포그라운드**로 한다. 반환된 후보를 곧바로 사용자 게이트에 써야 하므로, 완료를 기다렸다가 다음 단계로 간다. (writer 호출이 백그라운드인 것과 대비된다 -- writer 는 게이트 이후 단계다.)

<PENETRATE>
`knowledge-code-scanner` 호출은 포그라운드(`run_in_background: false`)로 한다. 반환된 후보 목록으로 곧바로 후보 게이트를 돌린다.
</PENETRATE>

### 스캐너 입력 포맷

Task 도구의 prompt 파라미터에 라벨 + 콜론 구조화 텍스트로 전달한다. JSON 형식은 쓰지 않는다.

| 필드 | 값 |
|------|----|
| `codebase_path` | 스캔 대상 경로 (`스캔 대상 경로` 에서 확보) |
| `language` | 확정 언어 (예: `cpp`) |
| `catalog_path` | 그 언어의 `languages/<lang>.md` 절대경로 |
| `knowledge_glob` | dedup 대조용 확정지식 Glob. 저장 경로가 속한 Herbarium 저장소의 `knowledge/**/*.md` |
| `wip_glob` | dedup 대조용 wip Glob. 같은 Herbarium 저장소의 `wip/*.md` |

`knowledge_glob` / `wip_glob` 은 활성 시 확보한 저장 경로가 속한 Herbarium 저장소 루트에서 구성한다. 스캐너는 이 Glob 으로 **파일명만** 대조해 이미 정리된 topic 을 후보에서 뺀다(본문은 안 읽음).

## 후보 게이트

스캐너가 반환한 후보 목록을 사용자에게 제시하고, 어떤 것을 wip 로 캡처할지 고르게 한다. 이것이 **스캔 모드의 유일한 사용자 질문**이다.

- 후보마다 `topic` · `usages`(실측 <=3개) · `why` 를 함께 보여 사용자가 판단할 근거를 준다.
- 사용자는 여럿을 한 번에 고를 수 있다. 고른 topic 각각을 캡처 대상으로 확정한다.
- 스캐너가 "카탈로그 보강 후보"(카탈로그 밖 발견)를 붙였으면 정식 후보와 구분해 참고로만 보여준다. 이는 사람이 카탈로그에 추가할지 판단할 몫이며, 이 게이트의 캡처 선택지로 올리지 않는다.
- 후보가 없으면("정리할 신규 비자명 문법 없음") 그대로 알리고 종료한다. writer 를 호출하지 않는다.

<PENETRATE>
스캐너 후보 목록을 사용자에게 제시하고, 사용자가 고른 topic 만 캡처 대상으로 확정한다.
</PENETRATE>

<RICOCHET>
사용자가 고르지 않은 후보를 임의로 캡처하지 않는다. "카탈로그 보강 후보" 를 정식 캡처 대상으로 올리지 않는다.
</RICOCHET>

## writer 위임

사용자가 고른 topic 마다 `knowledge-writer` 를 호출해 wip 본문 작성을 위임한다. 호출 형태·입력 포맷·저장 책임은 overview.md 의 `공유: knowledge-writer 호출` 섹션을 그대로 따른다(백그라운드 호출, 저장은 메인). 여러 topic 을 골랐으면 각각 백그라운드로 위임한다.

이 모드가 채우는 입력값은 다음과 같다.

| 필드 | 이 모드의 값 |
|------|-------------|
| `save_path` | 활성 시 확보한 저장 경로 |
| `topic` | 카탈로그의 정식 명칭 그대로 |
| `triggered_by` | `code-scan` |
| `trigger_summary` | 코드 스캔에서 발견된 문법임을 한 줄로 |
| `user_known` | `기초부터` -- 스캔 전제상 해당 문법을 모른다고 본다 |
| `discussion_context` | 스캔 대상·맥락 (어느 코드베이스를 왜 스캔했나) |
| `snippets` | 스캐너가 준 `usages`(코드 발췌 앵커) |
| `kind` | `code` (스캔 모드는 항상) |
| `language` | 확정 언어 |

<PENETRATE>
스캔 모드의 writer 입력은 `kind: code`, `triggered_by: code-scan`, `user_known: 기초부터` 로 채운다.
</PENETRATE>

## 미해결 질문 일괄 해소

스캔 배치의 writer 위임이 모두 끝나고 메인이 wip 파일을 전부 저장한 뒤, 저장된 wip 들의 "미해결 질문" 섹션을 확인한다. `[미해결 질문 없음]` 표식이 아니라 실제 미해결 항목이 하나라도 있으면, 그 항목들을 모아 사용자에게 제시하고 해결하고 넘어갈지 제안한다.

- 파일마다 중간에 묻지 않는다. 스캔 배치가 다 끝난 마지막에 한 번, 여러 wip 의 미해결 항목을 묶어 일괄로 제시한다.
- 사용자의 결정(노트 분리·병합, 표준 예제 선택 등)은 메인이 해당 wip 에 반영하고, 반영된 미해결 항목은 그 wip 에서 정리한다.
- 미해결이 하나도 없으면(모두 `[미해결 질문 없음]`) 이 단계는 조용히 건너뛴다.

이 일괄 해소는 코드 스캔 모드에만 적용한다. 모드 1(논의 감시)은 기존 작업 흐름의 방해를 줄이기 위해, 생성된 wip 에 미해결이 있어도 해소를 제안하지 않고 넘어간다.

<PENETRATE>
스캔 배치의 모든 wip 저장이 끝난 뒤, 미해결 질문이 있는 wip 들을 모아 마지막에 일괄로 사용자에게 해소를 제안한다.
</PENETRATE>

<RICOCHET>
스캔 중 wip 파일마다 미해결 해소를 중간중간 개별로 묻지 않는다.
</RICOCHET>

## 단계 시각화 (TaskCreate)

이 모드는 실행 단계가 드러나므로 진행을 TaskCreate 로 시각화한다. overview.md 의 `단계 시각화` 원칙을 따른다.

- 대상 경로 확보 · 언어 판정 같은 짧은 준비는 task 로 만들지 않는다.
- 스캐너 호출(포그라운드) -- 시작 시 in_progress, 반환 시 completed.
- 후보 게이트 -- 사용자에게 확인 요청 직전 completed, 응답 후 다음 task in_progress.
- writer 호출(백그라운드) -- 호출 즉시 completed ("위임 완료"). subject 는 "knowledge-writer 에이전트 호출" 형식. 고른 topic 마다 하나씩.
- 미해결 일괄 해소(미해결이 있을 때만) -- 사용자에게 제안하기 직전 completed, 응답 후 반영 task in_progress. 미해결이 없으면 task 를 만들지 않는다.
