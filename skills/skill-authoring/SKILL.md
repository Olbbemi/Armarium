# 스킬 저작

## 무엇을 하는가

아르마리움의 스킬을 만들고 고치는 절차와 규격을 제공한다. 규격 중 판정 가능한
것은 검사 스크립트가 판정하고, 나머지는 정해진 항목만 사람이 판정한다.

## 언제 쓰는가

새 스킬을 만들 때와 기존 스킬을 고칠 때 쓴다. 규격을 고칠 때도 쓴다.

## 왜 있는가

스킬을 만들 때마다 결과가 달라지는 것을 막는다. 서술 방식이 매번 다르면 같은
요청에 다른 스킬이 나오고, 같은 내용이 여러 곳에 적혀 고칠 때마다 어긋난다.
판정을 기계와 정해진 항목으로 옮겨 그 흔들림을 없앤다.

## 절차

아래 순서를 그대로 따른다. 단계를 건너뛰지 않는다.

### 1. 신규인지 수정인지 가른다

수정이면 대상 스킬의 `SKILL.md` 와 참조 파일을 읽는다. 바꿀 것이 규격인지
내용인지 가른다. 규격이면 검사도 같이 고친다.

### 2. 목적을 확정한다

무엇을 해결하고 언제 발동하는지를 사용자와 합의해 문장으로 못박는다. 발동
상황은 사용자가 실제로 할 법한 말로 [requests.md](requests.md) 에 적는다.
이것이 나오기 전에는 다른 파일을 만들지 않는다.

### 3. 완료 판정 기준을 적는다

내용을 쓰기 전에 적는다. 공통 규격 검사는 이미 있다. 그 스킬이 공통 규격에 없는
규격을 새로 정의하면 그 규격에 대한 검사를 추가한다.

### 4. 뼈대를 만든다

디렉토리와 파일을 배치한다. 배치 규칙은 [structure.md](../../standards/skills/structure.md)
를 읽고 그대로 따른다.

### 5. 내용을 쓴다

`description` 을 쓸 때 [trigger.md](../../standards/skills/trigger.md) 를 읽고 그대로 따르며,
트리거는 2단계에서 적은 요청 문장에서 뽑는다.
본문을 쓸 때 [writing.md](../../standards/skills/writing.md) 를 읽고 그대로 따른다.
`SKILL.md` 를 먼저 쓰고 참조 파일을 쓴다. 새 사실을 적을 자리를 정하기 전에
저장소 `CLAUDE.md` 의 문서 절을 적용한다.

### 6. 검사를 통과시킨다

다음을 실행한다. 실패가 0 이 될 때까지 고친다.

```
python3 checks/run.py
```

### 7. 다른 하네스의 검증을 받는다

만든 파일을 사용자가 다른 하네스 세션으로 옮기고, 거기서 나온 판정을 다시 가져온다.
하네스는 서로를 직접 부르지 못하므로 사용자가 옮긴다.

검증 대상은 8단계의 검토 항목과 같다. 누가 무엇을 검증하고 어떻게 기록하는지는
저장소 `CLAUDE.md` 의 검증 이력 절에 있다.

### 8. 사람이 검토한다

다음 항목을 사용자와 함께 본다. 7단계에서 받은 판정을 같이 놓고 본다.

```
T2  T3  T4  W1  W2  W3  W4  S5
```

각 항목의 내용과 판정 기준은 참조 파일에 있다. 저장소 `CLAUDE.md` 의 문서 절과
용어 표기 절도 같이 본다.

### 9. 승인을 받고 커밋한다

사용자 승인을 받은 뒤 커밋하고 버전을 올린다. 승인과 커밋 규칙은 저장소
`CLAUDE.md` 의 커밋 절에, 버전을 올리는 폭은 버전 절에 있다.
