# 로드맵 카탈로그 부트스트랩

overview 의 카탈로그 로드 단계에서 Glob 이 비었고 사용자가 부트스트랩을 고른 경우에만 도는 1회성 절차. 공개 로드맵을 조사해 CS 영역 목록과 영역별 항목 목록을 만들고 카탈로그 파일로 저장한다.

한 번 만들면 이후에는 돌지 않는다. 항목·영역을 나중에 더하는 것은 부트스트랩이 아니라 overview 의 `카탈로그 항목 추가` 소관이다.

---

## 왜 에이전트에 위임하나

조사량이 커서 메인이 직접 웹을 뒤지면 컨텍스트가 조사 결과로 찬다. `knowledge-roadmap-builder` 에이전트에 위임하고 메인은 결과만 받아 저장한다.

`knowledge-writer` 를 쓰지 않는 이유는 그 에이전트가 wip 본문 골격에 묶여 있어서다. 로드맵 카탈로그는 wip 가 아니라 목록이라 골격이 맞지 않는다.

---

## 실행 순서

### 1. 영역 확정

`knowledge-roadmap-builder` 를 `mode: domains` 로 한 번 호출해 CS 영역 목록 초안을 받는다.

- [ ] 에이전트 `knowledge-roadmap-builder`: 포그라운드 호출. 입력: `mode: domains`. 출력: 영역 목록(슬러그 + 한 줄 설명)을 최종 메시지로 반환

포그라운드로 호출하는 이유는 반환된 목록을 곧바로 사용자 게이트에 써야 하기 때문이다.

받은 초안을 사용자에게 보여주고 있다/없다를 손봐 확정한다. 이것이 부트스트랩의 유일한 실질 게이트다.

<FORBIDDEN>
사용자가 확정하지 않은 영역을 카탈로그 대상으로 삼지 않는다.
</FORBIDDEN>

### 2. 영역별 항목 채우기

확정된 영역마다 `knowledge-roadmap-builder` 를 `mode: items` 로 호출한다. 영역이 여럿이면 한 응답에 모두 넣어 병렬로 돌린다.

- [ ] 에이전트 `knowledge-roadmap-builder` (영역당 하나): 백그라운드 호출 (`run_in_background: true`). 입력: `mode: items` + `domain` + `domain_description`. 출력: 그 영역의 항목 목록(절 구분 + 슬러그 + 한 줄 설명 + 출처)을 최종 메시지로 반환

<FORBIDDEN>
영역이 여럿일 때 `mode: items` 호출을 여러 응답에 나눠 순차 실행하지 않는다.
</FORBIDDEN>

### 3. 저장

모든 영역의 통지가 도착하면 저장 직전에 요약을 한 번 보여주고 확인받는다. 요약은 "영역 N 개, 항목 M 개를 이렇게 저장합니다" 형식으로 영역별 항목 수를 함께 적는다.

항목 목록 자체에는 게이트를 두지 않는다. 영역당 수십 개라 전부 검토시키면 지치고, 항목 추가·삭제는 이후 언제든 되기 때문이다.

확인을 받으면 영역마다 `<roadmap경로>/<영역>.md` 로 저장한다. 파일 형식은 overview 의 `카탈로그 형식` 을 따른다.

반환 본문의 `&`/`<`/`>` HTML 엔티티는 저장 전 원복한다.

<FORBIDDEN>
영역 수·항목 수 요약을 사용자에게 확인받기 전에 카탈로그 파일을 쓰지 않는다.
</FORBIDDEN>

---

## 단계 시각화 (TaskCreate)

- 영역 조사(포그라운드) -- 시작 시 in_progress, 반환 시 completed
- 영역 확정 게이트 -- 확인 요청 직전 completed, 응답 후 다음 task in_progress
- 항목 조사(백그라운드) -- 호출 즉시 completed ("위임 완료"). subject 는 "knowledge-roadmap-builder 에이전트 호출 (<영역>)" 형식. 영역마다 하나씩
- 저장 확인 게이트 -- 요약 제시 직전 completed
- 카탈로그 저장(포그라운드) -- 시작 시 in_progress, 저장 완료 시 completed

---

## 부트스트랩 이후

저장이 끝나면 overview 의 카탈로그 로드 단계로 돌아가, 방금 저장한 파일을 Glob 해 영역 목록을 다시 얻는다. 갓 만든 카탈로그라 이후 진척 대조 결과는 대체로 전부 미착수다.
