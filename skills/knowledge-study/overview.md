# CS 로드맵 학습

computer science 영역별 로드맵 카탈로그를 기준으로, 아직 정리하지 않은 주제를 골라 wip 로 캡처하는 스킬.

명령 한 번에 시작해 끝나는 단발 작업이다. 로드맵을 열고, 오늘 볼 주제를 고르고, 위임하고 닫는다.

wip 를 확정지식으로 올리는 승급은 별도 스킬 `knowledge-promote` 가 담당한다. 본 스킬은 캡처까지만 다룬다.

---

## 활성 조건

사용자가 `/knowledge-study` 슬래시 명령으로 호출했을 때만 활성된다.

## 공용 프로토콜

공용 파일 둘이 각각 단일 출처다.

| 파일 | 담는 것 |
|------|--------|
| `references/herbarium-path.md` | 받은 경로가 Herbarium 인지 판정하는 절차 |
| `references/knowledge-wip-protocol.md` | `knowledge-writer` 호출 형태 · 입력 포맷 · 반환 본문 저장 |

활성 직후 둘 다 Read 툴로 로드해 따른다. 본 스킬은 경로를 둘 받으며(`경로 설정`) 받는 시점이 서로 다르다. 경로 검증 절차를 받은 경로마다 각각 적용한다.

| 파일 | 역할 |
|------|------|
| `skills/knowledge-study/bootstrap/bootstrap.md` | 카탈로그가 비었을 때 사용자가 고르면 도는 1회성 채우기 절차 |

| `knowledge-writer` | `agents/knowledge-writer.md` | 메인의 입력을 받아 wip 본문을 작성하고 반환 (저장은 메인이 수행) |

## 실행 순서

1. 활성 (`/knowledge-study` 슬래시 명령)
2. 공용 프로토콜을 로드하고 roadmap 경로를 확정한다 (`경로 설정`)
3. 카탈로그 로드 (`카탈로그 로드`)
4. wip 저장 경로를 확정한다 (`경로 설정`)
5. 진척 대조 (`진척 대조`)
6. 로드맵 제시 -- 영역을 고르게 하고, 이어서 그 영역의 미착수 항목에서 주제를 고르게 한다 (`로드맵 제시`)
7. `knowledge-writer` 호출 -- 백그라운드 (`run_in_background: true`). 입력: `writer 위임` 의 값. 출력: wip 본문을 반환
8. 저장과 보고 (`저장과 보고`) -- 통지를 기다리는 동안 6~7 을 다시 돌 수 있다

카탈로그가 없어 부트스트랩을 제안했는데 사용자가 물러나는 세션에까지 wip 경로를 요구하지 않는다.

### 단계 시각화 (TaskCreate)

- 경로 설정 · 카탈로그 로드 · 진척 대조는 Glob 몇 번이라 task 로 만들지 않는다
- 영역 선택 게이트 · 주제 선택 게이트 -- 확인 요청 직전 completed, 응답 후 다음 task in_progress
- writer 호출(백그라운드) -- 호출 즉시 completed ("위임 완료"). subject 는 "knowledge-writer 에이전트 호출" 형식. 고른 주제마다 하나씩
- 저장과 보고 -- 첫 통지가 도착할 때 in_progress, 마지막 저장이 끝나면 completed

## 경로 설정

이 스킬은 경로를 둘 받는다. 각각에 `references/herbarium-path.md` 의 검증 절차를 적용한다.

| 경로 | 용도 | 받는 시점 |
|------|------|----------|
| roadmap 디렉토리 | 영역별 카탈로그 파일이 있는 곳 | 활성 직후. 카탈로그를 로드하려면 먼저 있어야 한다 |
| wip 디렉토리 | writer 산출물을 저장할 곳 | 카탈로그 로드가 끝난 뒤. 진척 대조가 이 디렉토리를 Glob 하는 첫 지점이다 |

확정지식 디렉토리(`knowledge/`)는 roadmap 경로가 속한 저장소 루트에서 찾는다 -- 진척 대조에만 쓰는 읽기 전용 대상이다.

</FORBIDDEN>

## 카탈로그 로드

`<roadmap경로>` 를 Glob 해 영역 파일(`*.md`) 목록을 얻는다.

목록이 비면 곧바로 부트스트랩으로 넘어가지 않는다. 빈 결과는 카탈로그가 아직 없다는 뜻일 수도, 경로를 잘못 입력했다는 뜻일 수도 있다.

Glob 이 빈 사실과 확인한 경로를 알리고 두 갈래를 묻는다.

| 갈래 | 처리 |
|------|------|
| 부트스트랩 | `skills/knowledge-study/bootstrap/bootstrap.md` 를 Read 툴로 로드해 따른 뒤 이 단계로 돌아온다 |
| 경로 재입력 | `references/herbarium-path.md` 의 검증을 새 경로에 적용하고 이 단계를 다시 돈다 |

<FORBIDDEN>
Glob 결과가 비었다는 이유만으로 부트스트랩을 시작하지 않는다.
</FORBIDDEN>

## 카탈로그 형식

로드맵 카탈로그는 영역당 파일 하나다. 영역 목록은 `<roadmap경로>` 를 Glob 해서 얻으므로 별도 인덱스 파일을 두지 않는다.

```markdown
# 네트워크

> 출처: roadmap.sh/computer-science, Teach Yourself CS (2026-08-08 조사)

## 전송 계층
- `tcp-congestion-control` -- TCP 혼잡 제어
- `tcp-handshake` -- 연결 수립과 종료
- `head-of-line-blocking` (aliases: hol-blocking) -- 큐 선두 차단
```

| 요소 | 규칙 |
|------|------|
| 파일명 | `<영역>.md`. 영역 이름은 kebab-case 영어 |
| 최상위 헤딩 | 영역 이름 (한국어 가능) |
| 출처 줄 | 이 카탈로그를 무엇을 기준으로 만들었는지. 나중에 갱신할 때의 기준 |
| `##` 절 | 영역 안의 묶음. 인접 항목 판정에 쓴다 |
| 항목 | 백틱 슬러그 + `--` + 한 줄 설명. 슬러그는 kebab-case 영어 |
| `aliases` | 슬러그가 실제 노트 이름과 어긋날 때만 붙인다. 괄호 안에 쉼표로 나열 |

## 진척 대조

"무엇을 이미 정리했나" 는 매번 계산한다.

### 절차

1. `<wip경로>/*.md` 와 `<knowledge경로>/**/*.md` 를 Glob 해 파일명(확장자 뺀 것) 집합을 만든다.
2. 카탈로그 각 항목의 슬러그와 `aliases` 를 그 집합과 대조한다.
3. 아래 3상태로 판정한다.

| 상태 | 판정 조건 |
|------|----------|
| 미착수 | 어느 집합에도 없음 |
| wip 있음 | wip 집합에만 있음 |
| 확정 | knowledge 집합에 있음 |

파일명 뒤에 번호가 붙은 것(`<슬러그>-2.md` 등)도 같은 항목으로 친다.

앞에 언어가 붙은 파일(`cpp-coroutines.md` 등)은 대조 대상이 아니다. 그쪽은 특정 언어의 문법 노트이고, 카탈로그 항목은 언어에 매이지 않는 개념이라 별개다.

진척 상태를 파일이나 인덱스에 저장하지 않는다.
</FORBIDDEN>

## 로드맵 제시

진척 대조 결과를 두 단계로 보여준다.

1. 영역 선택 -- 영역별 진척 요약을 보여주고 하나를 고르게 한다. 요약 형식은 `<영역> <확정+wip 수>/<전체 항목 수>` 로 쓴다 (예: `network 3/12`).
2. 주제 선택 -- 고른 영역의 미착수 항목만 보여주고 하나를 고르게 한다. 항목마다 슬러그와 한 줄 설명을 함께 보여준다.

### 이미 있는 항목을 지목한 경우

사용자가 미착수가 아닌 항목을 굳이 지목하면 두 갈래를 묻는다.

- **보강** -- `triggered_by` 를 `roadmap-reinforce` 로 보내고 기존 파일 경로를 함께 넘긴다.
- **새로 쓰기** -- 기존과 무관하게 새로 쓴다. `triggered_by` 는 `roadmap` 이다.

어느 쪽이든 누적된 파일의 병합은 승급 단계 소관이다.

## 카탈로그 항목 추가

## writer 위임

호출 형태·입력 포맷·저장 책임은 공용 프로토콜의 `knowledge-writer 호출` 과 `반환 본문 저장` 을 그대로 따른다. 이 스킬이 채우는 입력값은 다음과 같다.

| 필드 | 이 스킬의 값 |
|------|-------------|
| `save_path` | 카탈로그 로드 뒤 확보한 wip 경로 |
| `topic` | 카탈로그 항목 슬러그 그대로 |
| `triggered_by` | `roadmap` 또는 `roadmap-reinforce` |
| `trigger_summary` | 어느 영역의 어떤 항목을 왜 골랐는지 한 줄 |
| `user_known` | `기초부터` 고정. 사용자가 이미 아는 주제를 골랐더라도 바꾸지 않는다 |
| `discussion_context` | CS 로드맵 기반 학습임을 밝히고, 상위 영역·절과 같은 절의 인접 항목을 적는다 |
| `snippets` | 카탈로그 항목 발췌 -- 항목명, 한 줄 설명, 상위 영역·절, 인접 항목 |
| `kind` | `concept` |

`snippets` 에는 대화 발췌도 코드 발췌도 넣을 것이 없다.

보강(`roadmap-reinforce`)이면 기존 노트의 절대경로를 `discussion_context` 에 함께 적어 writer 가 읽고 중복을 피하게 한다.

### triggered_by 값

| 값 | 뜻 |
|----|-----|
| `roadmap` | 사용자가 계획적으로 고른 미착수 주제. 막힌 것도 오해도 없다 |
| `roadmap-reinforce` | 이미 노트가 있는 항목의 보강 |

## 저장과 보고

위임한 주제 수만큼 완료 통지가 도착한다. 통지마다 반환 본문을 공용 프로토콜의 `반환 본문 저장` 대로 저장한다.

저장 직전에 이번 실행에서 이미 저장한 파일명과 겹치는지 보고, 겹치면 뒤에 번호를 더해(`<이름>-2.md`) 저장한다.

일부만 도착한 시점에 종료하지 않는다. 남은 위임이 있으면 그 통지까지 기다린다.

전부 저장하면 저장된 파일 경로를 목록으로 알리고 종료한다.

</FORBIDDEN>
