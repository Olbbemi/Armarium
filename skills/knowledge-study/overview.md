# CS 로드맵 학습

computer science 영역별 로드맵 카탈로그를 기준으로, 아직 정리하지 않은 주제를 골라 wip 로 캡처하는 스킬.

`knowledge-capture`(논의 감시)와 `knowledge-scan`(코드 스캔)이 반응형인 것과 달리 이 스킬은 능동형이다. 막힌 지점이나 눈앞의 코드가 아니라, 미리 세운 로드맵에서 주제를 골라 시작한다.

명령 한 번에 시작해 끝나는 단발 작업이다. 로드맵을 열고, 오늘 볼 주제를 고르고, 위임하고 닫는다.

wip 를 확정지식으로 올리는 승급은 별도 스킬 `knowledge-promote` 가 담당한다. 본 스킬은 캡처까지만 다룬다.

## 실행 순서

1. 활성 (슬래시 명령). 공용 프로토콜을 로드하고 두 경로를 확정한다 (`경로 설정`)
2. 카탈로그 로드 -- `<roadmap경로>` 를 Glob 해 영역 파일 목록을 얻는다. 없거나 비었으면 `skills/knowledge-study/bootstrap/bootstrap.md` 를 Read 툴로 로드해 따른 뒤 이 단계로 돌아온다
3. 진척 대조 (`진척 대조`)
4. 로드맵 제시 -- 영역을 고르게 하고, 이어서 그 영역의 미착수 항목에서 주제를 고르게 한다 (`로드맵 제시`)
5. 사전 질의 -- "이 주제 어디까지 아세요?" 한 번만 묻는다
6. `knowledge-writer` 호출 -- 백그라운드 (`run_in_background: true`). 입력: `writer 위임` 의 값. 출력: wip 본문을 반환 -> 메인이 `<wip경로>/<권장파일명>` 으로 저장
7. 반복 또는 종료 -- writer 가 백그라운드이므로 통지를 기다리는 동안 4~6 을 다시 돌 수 있다. 여러 주제를 연속으로 걸고 통지가 오는 대로 저장한다

### 단계 시각화 (TaskCreate)

- 경로 설정 · 카탈로그 로드 · 진척 대조는 Glob 몇 번이라 task 로 만들지 않는다
- 영역 선택 게이트 · 주제 선택 게이트 -- 확인 요청 직전 completed, 응답 후 다음 task in_progress
- writer 호출(백그라운드) -- 호출 즉시 completed ("위임 완료"). subject 는 "knowledge-writer 에이전트 호출" 형식. 고른 주제마다 하나씩
- wip 저장(포그라운드) -- 통지 도착 시 in_progress, 저장 완료 시 completed

## 경로 설정

이 스킬은 경로를 둘 받는다. 각각에 공용 프로토콜 1절의 검증 절차를 적용한다.

| 경로 | 용도 |
|------|------|
| roadmap 디렉토리 | 영역별 카탈로그 파일이 있는 곳 |
| wip 디렉토리 | writer 산출물을 저장할 곳 |

확정지식 디렉토리(`knowledge/`)는 roadmap 경로가 속한 저장소 루트에서 찾는다 -- 진척 대조에만 쓰는 읽기 전용 대상이다.

<FORBIDDEN>
확정지식 디렉토리 경로를 사용자에게 별도로 입력받지 않는다.
</FORBIDDEN>

## 카탈로그 형식

로드맵 카탈로그는 영역당 파일 하나다. 영역 목록은 `<roadmap경로>` 를 Glob 해서 얻으므로 별도 인덱스 파일을 두지 않는다.

```markdown
# 네트워크

> 출처: roadmap.sh/computer-science, Teach Yourself CS (2026-08-08 조사)

## 전송 계층
- `tcp-congestion-control` -- TCP 혼잡 제어
- `tcp-handshake` -- 연결 수립과 종료
- `head-of-line-blocking` (aliases: hol-blocking) -- 큐 선두 차단
```

| 요소 | 규칙 |
|------|------|
| 파일명 | `<영역>.md`. 영역 이름은 kebab-case 영어 |
| 최상위 헤딩 | 영역 이름 (한국어 가능) |
| 출처 줄 | 이 카탈로그를 무엇을 기준으로 만들었는지. 나중에 갱신할 때의 기준 |
| `##` 절 | 영역 안의 묶음. 인접 항목 판정에 쓴다 |
| 항목 | 백틱 슬러그 + `--` + 한 줄 설명. 슬러그는 kebab-case 영어 |
| `aliases` | 슬러그가 실제 노트 이름과 어긋날 때만 붙인다. 괄호 안에 쉼표로 나열 |

슬러그를 kebab-case 영어로 고정하는 이유는 진척 대조가 파일명 대조이기 때문이다. `wip/` `knowledge/` 의 파일명 관례와 맞아야 대조가 성립한다.

## 진척 대조

"무엇을 이미 정리했나" 는 매번 계산한다. 진척을 파일로 따로 두면 승급할 때마다 두 군데를 갱신해야 해서 반드시 어긋난다.

### 절차

1. `<wip경로>/*.md` 와 `<knowledge경로>/**/*.md` 를 Glob 해 파일명(확장자 뺀 것) 집합을 만든다.
2. 카탈로그 각 항목의 슬러그와 `aliases` 를 그 집합과 대조한다.
3. 아래 3상태로 판정한다.

| 상태 | 판정 조건 |
|------|----------|
| 미착수 | 어느 집합에도 없음 |
| wip 있음 | wip 집합에만 있음 |
| 확정 | knowledge 집합에 있음 |

파일명에 suffix 가 붙은 것(`<슬러그>-2.md` 등)도 같은 항목으로 친다. writer 가 충돌 시 suffix 를 증분하기 때문이다.

<FORBIDDEN>
진척 상태를 파일이나 인덱스에 저장하지 않는다.
</FORBIDDEN>

## 로드맵 제시

진척 대조 결과를 두 단계로 보여준다.

1. 영역 선택 -- 영역별 진척 요약을 보여주고 하나를 고르게 한다. 요약 형식은 `<영역> <확정+wip 수>/<전체 항목 수>` 로 쓴다 (예: `network 3/12`).
2. 주제 선택 -- 고른 영역의 미착수 항목만 보여주고 하나를 고르게 한다. 항목마다 슬러그와 한 줄 설명을 함께 보여준다.

기본 목록에 미착수만 올리는 이유는 중복 wip 를 막기 위해서다. writer 는 기존 파일을 덮어쓰지 않고 suffix 파일을 새로 만들 뿐이라, 같은 주제를 다시 고르면 중복이 쌓인다.

### 이미 있는 항목을 지목한 경우

사용자가 미착수가 아닌 항목을 굳이 지목하면 두 갈래를 묻는다.

- **보강** -- 기존 노트를 읽고 빠진 부분 위주로 쓴다. `triggered_by` 를 `roadmap-reinforce` 로 보내고 기존 파일 경로를 함께 넘긴다.
- **새로 쓰기** -- 기존과 무관하게 새로 쓴다. `triggered_by` 는 `roadmap` 이다.

어느 쪽이든 writer 는 덮어쓰지 않고 suffix 파일을 만든다. 누적된 파일의 병합은 승급 단계 소관이다.

## 사전 질의

주제를 고른 뒤 writer 를 부르기 전에 "이 주제 어디까지 아세요?" 를 한 번 묻는다. 받은 답이 `user_known` 이 된다.

로드맵 항목은 사용자가 직접 고른 것이라 배경 수준이 항목마다 다르다. 코드 스캔처럼 "모른다" 로 고정할 수 없어 물어야 깊이가 맞는다.

질문은 한 번만 한다. 로드맵을 훑는 리듬이 끊기지 않게 하기 위해서다. 사용자가 답하지 않으면 `user_known` 을 비운 채 그대로 호출한다 -- 캡처가 우선이다.

<FORBIDDEN>
사전 질의를 두 번 이상 반복하지 않는다.
</FORBIDDEN>

## 카탈로그 항목 추가

흐름 어디서든 항목을 더할 수 있다. 논의 중 "이것도 넣자" 가 나오면 해당 영역 파일에 항목을 추가하고, 새 영역이면 파일을 새로 만든다.

- 추가할 슬러그·설명·소속 절을 정해 사용자에게 보여주고 확인받은 뒤 쓴다.

<FORBIDDEN>
사용자가 요청하지 않았는데 카탈로그 변경을 커밋하거나 푸시하지 않는다.
</FORBIDDEN>

<FORBIDDEN>
추가할 항목을 사용자에게 보여주고 확인받기 전에 카탈로그 파일을 쓰지 않는다.
</FORBIDDEN>

## writer 위임

호출 형태·입력 포맷·저장 책임은 공용 프로토콜 2절·3절을 그대로 따른다. 이 스킬이 채우는 입력값은 다음과 같다.

| 필드 | 이 스킬의 값 |
|------|-------------|
| `save_path` | 활성 시 확보한 wip 경로 |
| `topic` | 카탈로그 항목 슬러그 그대로 |
| `triggered_by` | `roadmap` 또는 `roadmap-reinforce` |
| `trigger_summary` | 어느 영역의 어떤 항목을 왜 골랐는지 한 줄 |
| `user_known` | 사전 질의 답변 |
| `discussion_context` | CS 로드맵 기반 학습임을 밝히고, 상위 영역·절과 같은 절의 인접 항목을 적는다 |
| `snippets` | 카탈로그 항목 발췌 -- 항목명, 한 줄 설명, 상위 영역·절, 인접 항목 |
| `kind` | `concept` |

`snippets` 는 이 스킬에서 비는 칸이다. 대화 발췌도 코드 발췌도 없기 때문이다. 카탈로그 항목 자체가 그 앵커 역할을 한다 -- 무엇을 다뤄야 하는지의 범위를 고정해 준다.

보강(`roadmap-reinforce`)이면 기존 노트의 절대경로를 `discussion_context` 에 함께 적어 writer 가 읽고 중복을 피하게 한다.

### triggered_by 값

| 값 | 뜻 |
|----|-----|
| `roadmap` | 사용자가 계획적으로 고른 미착수 주제. 막힌 것도 오해도 없다 |
| `roadmap-reinforce` | 이미 노트가 있는 항목의 보강. 기존 노트를 읽고 빠진 부분 위주로 쓴다 |

`roadmap` 은 정정할 오해가 없다는 신호다. writer 는 정정 타깃 없이 표준 개론 골격으로 쓰되 출발 수준만 `user_known` 에 맞춘다.
