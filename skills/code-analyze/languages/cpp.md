# C++ 언어 규칙

## 노드 단위 (survey · structure 공통)

C++ 는 선언과 정의가 분리되므로, **같은 basename 의 헤더/소스 짝**(`Foo.hpp`+`Foo.cpp`, `Foo.h`+`Foo.cc`/`.cpp`)을 **한 노드**로 묶는다. 노드=파일 미러에서 이 짝은 파일 2개지만 노드 1개다.

- survey: 인벤토리/개수를 셀 때 이 짝을 한 노드로 센다 -- 헤더에 선언, 소스에 정의된 같은 타입/함수를 이중 계상하지 않는다.
- structure: 이 짝을 한 문서로 묶어 채운다 -- 선언의 시그니처 + 정의의 본문 속성(역할/불변식/예외)을 한 노드 문서에.
- 짝 없는 헤더-온리(템플릿/인라인 전용)나 소스-온리 파일은 그 하나가 곧 한 노드다.
- **노드 문서명 = 노드의 공통 basename(확장자 제거) + `.md`** -- 짝 `Foo.hpp`+`Foo.cpp` -> `Foo.md`, 소스-온리 `main.cpp` -> `main.md`, 헤더-온리 `Bar.hpp` -> `Bar.md`. 짝/소스-온리/헤더-온리 **일률로 stem** 을 쓰고, 소스-온리를 `main.cpp.md` 처럼 확장자째 적지 않는다(격리된 에이전트가 파일명에서 제각기 유추하면 같은 노드를 다른 이름으로 가리켜 링크가 끊긴다). survey 는 이 이름을 스켈레톤에 노드 식별자로 기록한다(단일 출처).

## 한정자 어휘 (structure)

범용 "가시성 / 수명 / 디스패치 축의 언어별 한정자"를 C++ 에서 채우는 구체 키워드. 전체 시그니처에 해당 한정자를 빠짐없이 남긴다(as-built).

- 가시성: `public` / `protected` / `private`.
- 수명 · 저장: `static`, `constexpr`, `constinit`, `inline`, `const`, `mutable`, `thread_local`.
- 디스패치: `virtual`, `override`, `final`.
- 계약 · 변환: `noexcept`, `explicit`.

## 속성 심화 (structure) -- C++ 고유 축

범용 "속성 3(역할 / 불변식 / 예외)"에 더해, 각 타입/함수에서 아래 C++ 축을 잡는다. 리팩토링 · 수명 버그 · 써야 할 테스트 지점이 여기서 드러난다.

- **소유권 / 수명 (소유 vs 관찰)**: 멤버 · 인자 · 반환이 자원을 **소유**하는지 **빌려 쓰는지** 명시한다.
  - **참조 · raw 포인터 = 비소유(빌림)** -- 수명은 다른 곳이 소유. 대표는 **주입된 의존**(생성자로 받은 의존을 참조 멤버로 보관). 그 수명이 무엇에 묶이고 언제 댕글링되는지 적는다.
  - **값 멤버 · 지역 변수 = 소유** -- 스코프/컨테이너가 수명 관리. 컴포지션 루트가 부품을 스택 값으로 소유해 참조로 배선하는 형태가 대표.
  - **스마트포인터** -- `unique_ptr`(단독) / `shared_ptr`(공유) / `weak_ptr`(비소유 관찰). RAII 핸들은 소멸자에서 자원 해제.
  - move-in 인자(값으로 받는 `unique_ptr` 등)는 **use-after-move 주의**.
- **값 시맨틱**: 기본은 **rule of 0**(특수 멤버 없이 컴파일러 기본 -- 순수 값 aggregate 는 이 한 줄로 족하다). 여기서 **벗어날 때만** 무게를 둔다 -- 복사/이동 생성 · 대입 · 소멸자를 직접 정의하거나 `=delete` / `=default` 하면, 그 상태와 거기서 나오는 **복사 가능 / 이동 가능 / 고정(pinned)** 여부, 이동 후 사용 위험을 적는다(자원 핸들 · 비소유 참조 보유 타입이 흔히 고정).
- **const 정확성**: 메서드의 const 여부(관찰 vs 변경), 인자의 `const&` / 값 / 비const& 구분, `mutable` 멤버. 어느 연산이 상태를 안 바꾸는지 = 불변식 · 스레드 안전 추론의 바탕. 관찰만 하는 메서드가 non-const 면 그 불일치를 짚는다.
- **인터페이스 / 추상 식별**: 순수 가상(`= 0`) 멤버가 있으면 이 타입이 **추상/인터페이스 타입**(직접 인스턴스화 불가, 파생이 채움)임을 표시한다. 다형적으로 삭제되는 기반 클래스의 **소멸자 virtual 여부**(다형 삭제 안전성)도 남긴다. 파생 -> 기반의 상속/구현 관계는 구조의 상속 관계로 적는다. 단 이를 "포트/어댑터" **역할로 해석하거나 포트 <- 구현 대응표를 만드는 것은 architecture 몫**이라 여기서 하지 않는다(같은 사실을 두 고도에서 이중 소유 방지 -- structure 는 낱개 구조 사실까지, 역할 지도는 architecture).
- **합타입(sum type) / 디스패치**: 타입이 `std::variant`(또는 닫힌 대안 집합)면 그 **대안 목록**과 **디스패치 방식**(`std::visit` + 오버로드 핸들러 등)을 적는다. 대안이 닫혀 있어 **망라(exhaustiveness)** 가 계약 -- 대안 추가 시 모든 방문자가 갱신돼야 하고, 각 대안별 핸들러가 테스트 단위가 된다.
- **`std::optional` 계약**: 시그니처에 `std::optional` 이 있으면 **부재/실패가 정상 결과**라는 계약이다 -- 반환 optional = 못 찾음/파싱 실패 등, 멤버/인자 optional = 미설정 가능. 그 부재 조건과 빈 경우 처리를 적는다(부정 경로 테스트의 후보).
- **`enum class` 도메인 의미**: enum 의 **값/순서 자체가 도메인 규칙**을 담으면(예: 정렬 우선순위가 enum 선언 순서와 일치) 그 의미를 적는다. enum <-> 저장/표시 토큰 매핑이나 범위 검증(외부가 int 캐스팅으로 넣은 잘못된 값 거부) 같은 **enum 계약**이 있으면 함께 -- 단일 어휘 출처로.

> 경계(structure vs invariants): 위는 모두 **낱개(per-node) 사실**이다. "모든 자원은 RAII 로 관리한다" 같은 **전칭 전역 규약**은 invariants 의 단일 소스이니, 여기서 전역 주장으로 올리지 말고 invariants 가 잡아 링크하게 둔다(structure = 낱개, invariants = 창발적 전역).
