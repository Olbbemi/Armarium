# skill-writing

이 플러그인(armarium)에서 스킬을 만들거나 고칠 때 따르는 **작성 규격 가이드** 스킬.

## 무엇을 하나

스킬의 파일 구조, 금지 규칙 태그 사용법, 프론트매터·description 작성법, overview 구성, 스킬 간 연결, 에이전트 구성 규약을 한곳에 정의한다.<br>
새 스킬을 만들거나 기존 스킬을 수정·재정비할 때 이 규격을 적용한다.

## 언제 쓰나

`/skill-writing` 호출, 또는 "스킬 만들어줘", "스킬 추가/수정해줘", "스킬 구조 어떻게 돼?" 처럼 스킬 작성 규격·기준이 필요할 때.

## 구조

단순 스킬 — `SKILL.md` + `overview.md` 만으로 구성된다. 모든 규격 내용이 `overview.md` 한 파일에 담겨 있다.

## 다루는 규격

| 항목 | 요지 |
|------|------|
| 언제 스킬을 만드나 | settings.json·CLAUDE.md로 되는 건 스킬로 만들지 않음 |
| 파일/디렉토리 구조 | 단순(overview 1개) vs 복합(하위 파일 분리). 단순/복합은 사용자 확인 후 결정 |
| 금지 규칙 태그 | `<FORBIDDEN>` 하나뿐이며 금지 규칙 전용. 수행 규칙은 태그 없이 실행 순서 단계(없으면 본문 항목)로 적는다. 붙일 조건은 무검출 -- "어기면 무엇이 잡아내는가" 에 답이 있으면 산문. 한 블록에 금지 하나, 파일당 18개 상한 |
| 프론트매터 | `SKILL.md`에만. `name`(영문)·`description`(한국어)·`created` |
| description | 호출 판단 기준 — 상황·증상·사용자 발화만, 동작 요약·지시문 금지 |
| overview | 복합 스킬은 `## 하위 스킬`·`## 실행 순서` 필수, 실행 단계에 TaskCreate 시각화 지시 포함 |
| 스킬 간 연결 | 경로는 플러그인 루트 기준, Read 툴로 참조 |
| 언어 / 형식 | 본문 한국어, 이모지·은유 표현 금지, 불릿·헤딩·bold 사용 기준 |
| 본문에 넣지 않는 것 | 결정의 정당화·시점 서사·재진술은 본문에서 뺀다. 판정은 삭제 테스트. 근거라 남기는 문장에서도 시점 표기는 걷어낸다 |
| 예시 작성 | 휘발성 참조(커밋 해시 등)·프로젝트 고유 식별자는 빼고, 재현 가능한 패턴으로 서술 |
| 에이전트 구성 | Task 서브에이전트 정의는 플러그인 루트 `agents/` 에, 생성 전 사용자 승인 |

## 함께 쓰는 스킬

작성·수정한 스킬이 이 규격을 지켰는지 검증하려면 [`skill-verify`](../skill-verify/README.md)를 쓴다.

## 주의

- 단순/복합 판단은 Claude 자체 판단만으로 결정하지 않고 사용자 확인을 받는다.
- 본문에 산문으로 적힌 금지 규칙은 무검출 조건을 통과하면 `<FORBIDDEN>` 태그로 변환한다.
- 중요해 보인다는 이유만으로 태그를 붙이지 않는다. `skill-verify` 의 검사 항목·절차의 다음 단계·산출물 중 하나라도 그 위반을 잡아내면 산문으로 둔다.
- 파일당 18개 상한은 이상치 경보다. 넘으면 개수를 맞추려 지우지 말고 무검출로 다시 판정하며, 그래도 남으면 상한을 두어 개 올리거나 파일을 쪼갠다.
