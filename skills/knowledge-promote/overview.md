# 지식 승급 (promote)

캡처 스킬들(`knowledge-capture` · `knowledge-scan` · `knowledge-study`)이 쌓은 wip 초안을 확정지식으로 가공해 전역 지식 저장소에 올리는 스킬. 세 스킬 모두 같은 형식의 wip 를 같은 디렉토리에 쌓으므로, 승급은 누가 만들었는지 따지지 않는다.

---

## 활성 조건

사용자가 `/knowledge-promote` 슬래시 명령으로 호출했을 때만 활성된다.

---

## 하위 스킬

| 파일 | 역할 |
|------|------|
| `skills/knowledge-promote/format/format.md` | 확정지식 형식 규격 -- 프론트매터 칸 · 언어별 공식 문서 · 본문 표기 규칙 · 코드 지식 구성 |
| `references/knowledge-repos.md` | 네 knowledge 스킬 공용 -- 경로가 등록된 지식 저장소인지 판정 |
| `references/knowledge-wip-sections.md` | writer 와 공용 -- wip 섹션의 제목·앵커·강제 여부. `2. 형식 변환` 이 로드를 지시한다 |

에이전트는 쓰지 않는다.

---

## 경로 설정

경로가 등록된 지식 저장소인지 판정하는 규약은 아래 공용 파일이 단일 출처다.

    references/knowledge-repos.md

활성 직후 이 파일을 Read 툴로 로드해 따른다. 본 스킬이 사용자에게 받는 경로는 지식 저장소 루트 하나이며, 공용 파일의 검증 절차를 그 경로에 적용한다.

채택한 루트 하위에서 wip 폴더(`<루트>/wip`)와 확정지식 디렉토리(`<루트>/knowledge`)를 도출한다.

<FORBIDDEN>
wip 폴더나 확정지식 디렉토리 경로를 사용자에게 별도로 입력받지 않는다.
</FORBIDDEN>

---

## 산출물 범위

이 스킬이 만드는 것은 `knowledge/<id>.md` 마크다운뿐이다. HTML 생성, 사이트 빌드, 사이트 기반 파일(설정·레이아웃·스타일·인덱스·워크플로) 관리는 모두 대상 저장소 소관이며 범위 밖이다.

마크다운은 특정 렌더러가 아니라 이식성을 기준으로 쓴다. 어느 뷰어로 열어도 의도대로 보이는 표기를 택하며, 표기 규격은 `format/format.md` 가 정한다.

대상 저장소가 자기 렌더 설정 때문에 요구하는 표현 규약(작성 형식·회피할 문법)이 있으면 그 저장소의 규칙 파일(`CLAUDE.md` 등)이 정하고, 승급은 그것을 따른다.

<FORBIDDEN>
대상 저장소의 렌더 설정이나 레이아웃 파일을 읽어 형식 규격을 바꾸지 않는다.
</FORBIDDEN>

---

## 실행 순서

활성 직후 위 "경로 설정" 을 먼저 수행해 wip · knowledge 경로를 확정한 뒤, 아래 순서로 진행한다.

1. 대상 선택
2. 형식 변환
3. 관계 추출
4. 일반화
5. 검증
6. 중복·충돌 점검
7. 브랜치 생성·체크아웃
8. 초안 저장 후 사용자 검토·승인
9. 커밋
10. 종료 보고

### 1. 대상 선택

TaskCreate 로 "1. 대상 선택" task 를 등록하고 in_progress 로 설정한다. 대상 wip 가 결정되면 completed 로 닫는다.

채택한 wip 디렉토리를 Glob 해 목록을 보여주고 사용자가 하나를 고르게 한다. 한 번에 하나의 wip 만 승급한다.

목록이 비면 승급할 초안이 없는 것이다. 그 사실과 확인한 경로를 알리고 여기서 끝낸다.

#### 미해결 질문 선행 게이트

고른 wip 의 `미해결 질문` 섹션을 읽는다. 사람 판단이 필요한 열린 사안이라 승급 전에 닫아야 한다.

| 상태 | 처리 |
|------|------|
| `[미해결 질문 없음]` 표식 한 줄 | 통과 |
| 모든 항목 끝에 `[해결 완료]` 마커 | 통과 |
| 마커 없는 항목이 하나라도 있음 | 그 항목들을 사용자에게 제시해 함께 해소하고, 해소한 항목 끝에 `[해결 완료]` 를 붙여 wip 를 갱신한 뒤 진행한다 |
| 섹션 자체가 없음 | writer 누락을 의심해 사용자에게 확인한다 |

`조사 보류 목록` 은 이 게이트의 대상이 아니다. 출처만 확인하면 되므로 `5. 검증` 이 처리한다. 거기서 출처로도 확정 못 한 항목만 확정지식 `미해결 질문` 으로 남는다.

<FORBIDDEN>
해소되지 않은 미해결 질문이 남은 wip 의 형식 변환을 시작하지 않는다.
</FORBIDDEN>

### 2. 형식 변환

TaskCreate 로 "2. 형식 변환" task 를 등록하고 in_progress 로 설정한다. 형식 변환이 완료되면 completed 로 닫는다.

wip 산문을 확정지식 형식(프론트매터 + 정제 본문)으로 바꾼다. 이 단계에 들어올 때 아래 두 파일을 Read 툴로 로드해 따른다.

    skills/knowledge-promote/format/format.md
    references/knowledge-wip-sections.md

이후 3·4·5 단계가 섹션을 지목할 때도 뒤의 앵커를 기준으로 삼는다.

`kind`(`concept` 또는 `code`)가 본문 구성을 가르며, 그 값은 wip 맨 위 `<!-- wip-meta: ... -->` 주석에서 읽는다. `relations` 는 3단계가, `summary` 는 4단계가 채운다 -- 이 단계에서는 비워 둔다.

### 3. 관계 추출

TaskCreate 로 "3. 관계 추출" task 를 등록하고 in_progress 로 설정한다. 추출이 완료되면 completed 로 닫는다.

`wip:relations` 섹션과 본문 언급을 relations 타입드 엣지로 만든다. 종류 4개:

- `contrasts_with` — 같은 역할의 반대/경쟁 선택지
- `same_family` — 같은 계열의 동료
- `part_of` — 부분-전체 종속 (하위가 상위의 일부). 예: views 는 Ranges 의 일부
- `related` — 그 밖에 엮인 연관 개념 (종류 미분류)

대상은 다른 확정지식의 id 다. 채택한 knowledge 디렉토리를 Glob 으로 보고 실재 id 와 우선 연결한다.

저장 포맷 -- relations 는 `타입:대상` 문자열의 평탄 리스트로 frontmatter 에 둔다. 중첩 맵을 쓰지 않는다.

```yaml
relations: [contrasts_with:characterization-test, same_family:bdd, part_of:ranges, related:unit-test]
```

종류 남발은 피한다. 위 4종으로 안 잡히는 더 세밀한 세분화는 사용자가 필요하다고 판단하기 전까지 도입하지 않는다.

<FORBIDDEN>
가리키는 id 파일이 아직 없다는 이유로 그 관계를 relations 에서 빼지 않는다.
</FORBIDDEN>

### 4. 일반화

TaskCreate 로 "4. 일반화" task 를 등록하고 in_progress 로 설정한다. 완료되면 completed 로 닫는다.

확정지식은 전역이라 특정 프로젝트에 종속된 부분이 남지 않게 한다. `wip:project-context` 격리 블록(프로젝트 이름·언어·규모·아키텍처·그 프로젝트의 결정)은 확정지식에서 삭제하거나 압축한다. 보편 서술은 "본 프로젝트는 ..." 대신 조건 서술("...할 때")로 다듬는다. 본문 `미해결 질문` 은 그 주제에 보편적인 항목만 남기고 특정 프로젝트의 결정은 뺀다.

프로젝트 특유 요소는 산문에만 있지 않다. 코드 예제·발췌(특히 code-scan 유래 wip)에 든 스캔 원본의 프로젝트 고유 식별자(함수·타입·변수명)는 범용 이름으로 치환한다.

본문이 여기서 최종 형태가 되므로 프론트매터 `summary` 를 이 시점에 쓴다. 정리된 본문을 대표하는 문장으로 쓰고, wip 의 `wip:summary` 는 초안으로만 참고한다. 표기 규격은 `format/format.md` 의 `summary 표기` 를 따른다.

<FORBIDDEN>
프로젝트 특유 전제를 `summary` 에 적지 않는다.
</FORBIDDEN>

`wip:project-context` 가 `[전제 없음]` 표식 한 줄이면, writer 가 검토 후 분리할 프로젝트 특유 요소가 없다고 판단한 것이다. 이때는 본문을 그대로 통과시키고 추가로 제거할 프로젝트 특유 요소를 찾지 않는다(표식 줄만 strip). 반대로 그 섹션이 표식도 내용도 없이 진짜 비었거나 섹션 자체가 없으면 writer 누락을 의심해, 본문에 프로젝트 특유 요소가 남아 있는지 한 번 더 점검하고 의심되면 사용자에게 확인한다.

<FORBIDDEN>
코드 예제·발췌에 스캔 원본 프로젝트의 고유 식별자를 그대로 남기지 않는다.
</FORBIDDEN>

### 5. 검증

TaskCreate 로 "5. 검증" task 를 등록하고 in_progress 로 설정한다. 검증이 완료되면 completed 로 닫는다.

- `wip:references` 의 URL 이 살아있는지 WebFetch 로 확인한다. 죽은 링크는 사용자에게 보고한다. URL 이 꺾쇠(`<url>`) 또는 `[라벨](url)` 형식인지 함께 확인하고, bare URL 이면 교정한다.
- `wip:pending-research`(writer 가 조사 차단으로 못 메운 항목)를 처리한다. 각 항목의 출처를 실제 WebFetch 로 가져와 본문의 대응 `[미검증 #N]` 마커 위치와 대조하고, 어긋나면 정정한다. 항목의 `차단` 표기에 따라 갈린다 -- 권한 거부는 promote 가 포그라운드라 사용자 일회 승인(등록 없이)을 받으면 fetch 가 성공한다. 서버 `403` 은 포그라운드여도 성공하지 못하므로 같은 사실을 담은 다른 출처를 찾거나 WebSearch 결과로 확인한다. 검증으로 확정된 항목은 보류 목록에서 내리고 본문의 `[미검증 #N]` 마커를 지운다. 이 마커와 보류 목록은 wip 전용이라 확정지식 최종본에 남기지 않는다.
- 사용자가 fetch 승인을 거부하거나 출처로도 확정 못 한 항목은 본문 `미해결 질문` 으로 옮겨 잔류시킨다.
- `wip:full-example` 을 실제로 컴파일·실행해 통과를 확인한다. 순수 illustration 코드(실행할 API 가 아님)는 대상이 아니다.
  - 컴파일러·런타임 부재 등으로 못 돌리면(검증 불가) "검증 불가" 로 사용자에게 보고한다.
  - 빌드는 됐는데 실패하면(검증 실패 = 코드 결함) 메인이 명백한 누락(빠진 include 등)을 정정해 재빌드한다. 몇 차례로도 통과 못 하면 8단계 이슈로 사용자에게 보고한다(자동 무한 정정은 하지 않는다).
- 사실성이 의심되는 서술은 표시해 사용자 확인 항목으로 남긴다.

<FORBIDDEN>
조사 보류 목록에서 검증되지 못한 미검증 서술을 확정지식 본문에 단정형으로 올리지 않는다.
</FORBIDDEN>

### 6. 중복·충돌 점검

TaskCreate 로 "6. 중복·충돌 점검" task 를 등록하고 in_progress 로 설정한다. 점검이 완료되면 completed 로 닫는다.

`knowledge/` 의 기존 확정지식과 summary 를 비교해 의미적으로 겹치는 후보를 찾는다. 중복(같은 주제) 또는 충돌(같은 주제, 다른 서술)이 의심되면 병합·대체·별도 중 무엇이 맞는지 사용자에게 묻는다.

고른 갈래가 뒤 단계의 대상 파일과 브랜치명을 가른다. 겹치는 후보가 없으면 묻지 않고 별도로 본다.

| 갈래 | 대상 id | 8단계가 쓰는 파일 |
|------|--------|------------------|
| 별도 | 새 id | `<knowledge>/<새 id>.md` 신규 생성 |
| 병합 | 기존 id | `<knowledge>/<기존 id>.md` 를 읽어 이번 내용을 반영해 다시 쓴다 |
| 대체 | 기존 id | `<knowledge>/<기존 id>.md` 의 기존 내용을 버리고 이번 변환 결과로 전체를 덮어쓴다 |

<FORBIDDEN>
병합을 고른 사용자에게 기존 파일 내용을 덜어낸 결과를 내지 않는다.
</FORBIDDEN>

### 7. 브랜치 생성·체크아웃

TaskCreate 로 "7. 브랜치 생성·체크아웃" task 를 등록하고 in_progress 로 설정한다. 브랜치 생성 및 체크아웃이 완료되면 completed 로 닫는다.

승급 산출을 main 에 직접 넣지 않고 브랜치에서 격리한다.

브랜치명과 기존 브랜치 재사용 여부는 대상 저장소가 정한다. 채택한 저장소 루트의 규칙 파일(`CLAUDE.md` 등)에 승급 워크플로가 있으면 그것을 따르고, 없으면 `promote/<YYYY-MM-DD>` 로 만든다.

1. 현재 브랜치가 main 인지 확인하고, main 이 아니면 먼저 main 으로 이동한다.
2. 대상 브랜치가 이미 있으면 체크아웃해 재사용하고, 없으면 main 을 base 로 생성한다.

### 8. 초안 저장 후 사용자 검토·승인

TaskCreate 로 "8. 확정지식 초안 저장" task 를 등록하고 in_progress 로 설정한 뒤, 7단계에서 만든 브랜치의 `<knowledge>/<id>.md` 로 변환 초안을 먼저 저장한다. 저장이 끝나면 completed 로 닫는다. 이어서 TaskCreate 로 "8. 사용자 검토·승인" task 를 등록하고 in_progress 로 설정한다. 검토를 요청하기 직전 completed 로 닫고, 응답을 받아 다음 단계로 간다.

저장한 파일 경로를 알리고, 5·6 단계의 이슈(죽은 링크, 사실성 의심, 중복·충돌 후보)만 대화창에 함께 제시해, 사용자가 파일을 직접 열어 검토·승인하게 한다. 사용자가 수정을 요청하면 파일을 고쳐 다시 검토받는다.

<FORBIDDEN>
변환 초안 본문을 대화창에 통째로 출력하지 않는다.
</FORBIDDEN>

<FORBIDDEN>
사용자 승인을 받지 않은 초안을 9단계 커밋으로 넘기지 않는다.
</FORBIDDEN>

### 9. 커밋

TaskCreate 로 "9. 커밋" task 를 등록하고 in_progress 로 설정한다. 커밋이 완료되면 completed 로 닫는다.

승급 산출(`knowledge/<id>.md`)을 7단계에서 만든 브랜치에 커밋한다. 커밋 메시지 형식은 갈래를 따른다.

| 갈래 | 커밋 메시지 |
|------|------------|
| 별도 | `Promote <id> to knowledge` |
| 병합 | `Merge <wip topic> into <id>` |
| 대체 | `Replace <id> with promoted <wip topic>` |

<FORBIDDEN>
사용자가 요청하지 않았는데 커밋한 브랜치를 푸시하지 않는다.

### 10. 종료 보고

TaskCreate 로 "10. 종료 보고" task 를 등록하고 in_progress 로 설정한다. 보고가 끝나면 completed 로 닫는다.

아래를 한 번에 알리고 끝낸다.

- 저장된 확정지식 파일 경로와 브랜치명
- 5·6 단계에서 미해결로 남은 이슈 (검증 불가 예제, 죽은 링크, 중복·충돌 후보)

## 다루지 않는 것

- 마크다운 -> SQLite/벡터 빌드, 임베딩, 그래프 시각화는 본 스킬 범위 밖이다.
- 여러 wip 를 한 번에 승급하는 배치 처리는 본 스킬 범위 밖이다.
- 승급이 끝난 원본 wip 의 정리는 본 스킬 범위 밖이다. 사람이 필요할 때 직접 지운다.
