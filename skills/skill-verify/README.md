# skill-verify

만들어진 스킬이 [`skill-writing`](../skill-writing/README.md) 규격과 의도대로 동작하는지 검증하는 스킬.

## 무엇을 하나

대상 스킬을 7개 항목으로 검사하고, 결과를 보고서 파일로 저장한 뒤 대화창에는 요약 테이블과 저장 경로만 출력한다.

## 언제 쓰나

`/skill-verify` 호출, 또는 "이 스킬 제대로 만들어진 거 맞아?", "스킬 검증해줘" 처럼 스킬 구조·description·실제 동작 확인이 필요할 때.

## 구조

- `overview.md` — 진입점. 실행 순서·결과 취합 정의
- `checks/*.md` — 검증 절차의 단일 출처 7개 (structure / frontmatter / description / tag / format / agent / behavior)
- 검증 에이전트 5개 (플러그인 루트 `agents/skill-verify-*.md`) — 2단계 병렬 실행

## 검증 항목 7가지

| 항목 | 실행 주체 |
|------|----------|
| 구조 검증 | 메인 (1단계 게이트) |
| 프론트매터 검증 | 에이전트 `skill-verify-frontmatter` (2단계 병렬) |
| Description 검증 | 에이전트 `skill-verify-description` (2단계 병렬) |
| 금지 규칙 태그 검증 | 에이전트 `skill-verify-tag` (2단계 병렬). `<FORBIDDEN>` 만 허용. 하드 실패는 이름·형식·금지명령·과잉 태그·총량 18. 중복과 누락은 권고 후보로만 보고 |
| 형식·언어 검증 | 에이전트 `skill-verify-format` (2단계 병렬). 은유와 실행에 안 쓰이는 서술은 권고 후보로 보고 |
| 에이전트 검증 | 에이전트 `skill-verify-agent` (2단계 병렬, 조건부) |
| 동작 검증 | 메인 (3단계 마무리) |

## 동작 흐름

1. **검증 대상 확인** — 시작 전 대상 스킬의 `SKILL.md` 경로를 사용자에게 확인
2. **사전 준비** — `<대상 스킬 디렉토리>/wip/` 와 `<프로젝트 루트>/.claude/verify/<스킬>/` 생성. wip 경로에 시험 쓰기를 해 사전 허용 여부를 확인 (백그라운드 에이전트는 권한 프롬프트를 못 띄운다)
3. **1단계 구조 검증(게이트)** — 메인이 직접. 실패 시 즉시 중단
4. **2단계 병렬 검증** — 5개 에이전트를 한 응답에 모두 백그라운드 호출
5. **3단계 동작 검증** — 2단계와 병렬로 메인이 Read 로 로드 흐름 시뮬레이션
6. **결과 취합** — 5개 통지가 모두 도착하면 wip 7개를 모아 보고서 작성, wip 정리

## 출력

- **보고서** — `<프로젝트 루트>/.claude/verify/<스킬>/result.md`. `<프로젝트 루트>` 는 대상 스킬 디렉토리에서 `git rev-parse --show-toplevel` 로 구한 그 스킬의 프로젝트 루트 (현재 작업 디렉토리나 이 플러그인 루트가 아님)
- **대화창** — 항목별 통과/실패 요약 테이블 + 보고서 저장 경로만

## 주의

- 검증 범위는 스킬 디렉토리만이 아니다. 그 스킬이 Task 로 호출하는 플러그인 루트 `agents/` 정의와 본문이 Read 하는 공유 참조 파일(`references/` 등)까지 태그·형식 검사 대상이다.
- 보고서는 대상 스킬 디렉토리 안에 저장하지 않는다 (추가 마크다운으로 오인 방지).
- 5개 에이전트는 한 응답에 동시·백그라운드로 호출해야 병렬 효과가 난다.
- 5개 백그라운드 통지가 모두 도착한 뒤에만 결과를 취합한다.
