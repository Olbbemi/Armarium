# 형식·언어 검증

이 파일은 overview.md 의 실행 순서에 따라 메인 Claude 가 직접 로드한다.

대상 스킬이 `skill-writing §8 언어 규칙` 과 `§9 작성 형식 규칙` 을 따르는지 확인한다.
대상 범위는 SKILL.md, overview.md, 그리고 모든 하위 파일이다.

---

## 체크리스트

### 형식 규칙 (§9)

- [ ] 본문에 이모지가 없다
- [ ] 단일 서술문에 불릿(`-`, `*`)이 사용되지 않았다 (불릿 항목은 항상 2개 이상이어야 한다)
- [ ] 헤딩(`####` 등)과 bold(`**...:**`)가 용도에 맞게 사용되었다 -- 독립적 내용 블록(설명·예시 포함)은 헤딩, 짧은 분류 레이블(good/bad, 해야 할 것/하지 말 것 등)은 bold

### 언어 규칙 (§8)

- [ ] SKILL.md 프론트매터의 `name` 필드가 영어다
- [ ] SKILL.md 프론트매터의 `description` 필드가 한국어다
- [ ] 본문 전체가 한국어다 (사용자가 별도 지정한 영역, 코드 블록, 파일 경로/식별자, 인용된 영문 용어는 예외)

### 은유 표현 (§9, 권고)

이 항목은 통과/실패를 가르지 않는 **권고 검사**다. 은유 여부는 의미 판단이라 세션마다 갈릴 수 있어 하드 실패로 처리하지 않고 검토 후보만 올린다.

- 스킬 문서에서 다른 사물에 빗댄 은유·비유 표현을 찾아 후보로 모은다.
- 은유인지 굳어진 용어인지 애매하면 배제하지 말고 후보에 넣는다 -- 최종 판단은 사용자가 한다.

---

## 판단 가이드

판단이 모호한 경우 다음 기준을 따른다.

- 영문 식별자(`PENETRATE`, `RICOCHET`, `description`, 파일명 등)는 본문 한국어 규칙 위반으로 간주하지 않는다.
- 짧은 레이블에 헤딩이 쓰였는지 판별이 어려우면, "그 항목 아래에 본문이 한 단락 이상 따라오는가" 로 본다. 본문이 따라오면 헤딩이 맞고, 한 줄 안에 끝나는 분류 레이블이면 bold 가 맞다.
- 이모지 판단은 유니코드 이모지(예: 그림 문자, 기호 이모지)만 본다. 일반 화살표 같은 ASCII 기호는 이모지가 아니다.
- 은유는 확신할 때만 후보에서 뺀다. 굳어진 준기술어(앵커, 창발, 지도 등)만 제외하고, 다른 사물에 빗댄 표현(씨앗, 척추, 금광 류)이 조금이라도 의심되면 올린다.

## 결과 보고

체크리스트 각 항목을 실행한 뒤 아래 형식으로 출력한다.

```
- [o] 항목명
- [x] 항목명 -- 실패 이유
  > "문제가 된 원문 인용"
  위치: <파일 경로>

**결론:** 통과/실패 -- 통과 N / 실패 N
**수정 제안:** (실패 항목별 수정 방법, 없으면 생략)
```

은유 권고는 통과/실패와 별개로 아래처럼 덧붙인다. 후보가 없으면 생략한다.

```
**은유 검토 후보** (권고, 통과/실패 무관)
- "원문 인용" -- 위치: <파일 경로> -- 사유: <은유로 의심되는 까닭>
```

<PENETRATE>
`[x]` 표기 항목이 하나라도 있으면 결론은 실패다.
</PENETRATE>
