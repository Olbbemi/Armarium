# 금지 규칙 태그 검증

이 파일은 overview.md 의 실행 순서에 따라 메인 Claude 가 직접 로드한다.

대상 스킬의 `<FORBIDDEN>` 태그가 `skill-writing §3` 규약을 따르는지 확인한다.
대상 범위는 SKILL.md, overview.md, 그리고 모든 하위 파일이다.

---

## 태그 규약 (요약)

태그는 `<FORBIDDEN>` 하나이며 금지 규칙 전용이다. 본문은 "~하지 않는다 / ~금지" 형태의 금지 명령이다.
반드시 해야 할 일에는 태그를 쓰지 않고 실행 순서의 단계로 적는다.

붙일 조건은 무검출 하나다.

> 이 규칙을 어기면 무엇이 그것을 잡아내는가.

`skill-verify` 의 개별 검사 항목, 절차의 다음 단계, 산출물 자체 중 하나라도 그 위반을 잡아내면 산문으로 적는다.
아무것도 잡아내지 못할 때만 태그로 감는다.

---

## 체크리스트

### 태그 이름

- [ ] 모든 태그 블록이 `<FORBIDDEN>` 이다

### 태그 내부 작성 형식

- [ ] 태그 내부에 불릿(`-`, `*`)이 사용되지 않았다
- [ ] 태그 내부에 헤딩(`#`)이 사용되지 않았다
- [ ] 태그 내부에 표가 사용되지 않았다
- [ ] 태그 내부에 의도적인 들여쓰기 구조가 없다
- [ ] 각 태그 블록 안에는 평문 단락 하나만 들어 있다
- [ ] 한 태그 블록에 금지 규칙이 둘 이상 들어 있지 않다

마지막 항목은 문장 수로 센다. 블록 본문을 문장 단위로 끊어 금지 명령이 둘 이상이면 위반이며, 각각 별도 블록으로 나누라고 보고한다. 앞 문장을 보충하는 근거·조건절은 별도 규칙으로 세지 않는다.

### 금지 명령 여부

- [ ] 모든 태그 내부 문장이 금지 명령("~하지 않는다", "~금지") 형태다
- [ ] 수행 명령("~한다")을 태그로 감은 것이 없다

수행 명령이 태그로 감겨 있으면, 그 내용을 실행 순서의 단계나 산문으로 내리라고 보고한다.

### 무검출 조건 위반 (과잉 태그)

태그마다 그 위반을 잡아낼 장치가 있는지 대조한다. 대조 대상은 `skills/skill-verify/checks/` 의 여섯 검사 파일과, 대상 스킬 자신의 실행 순서다.

- [ ] 잡아내는 장치가 있는데 태그로 감긴 것이 없다

위반 항목마다 원문과 함께 **어느 검사 파일의 어느 항목이 그것을 잡는지**를 인용해 보고한다. 잡는 항목을 지목하지 못하면 위반으로 올리지 않는다.

### 같은 규칙 중복 (권고)

이 항목은 통과/실패를 가르지 않는 **권고 검사**다. 태그와 산문이 같은 규칙을 말하는지는 의미 판단이라 세션마다 갈리고, 태그된 규칙을 설명하는 산문은 무엇이든 후보가 되어 판정이 끝나지 않는다. 하드 실패로 처리하지 않고 검토 후보만 올린다.

- 태그와 같은 규칙을 그대로 되풀이하는 산문을 찾아 후보로 모은다.
- 무검출을 통과한 태그면 산문 쪽 규칙 서술을 걷어내는 방향, 통과하지 못했으면 태그를 지우는 방향으로 제안한다.
- 산문이 근거·절차·정의를 담고 있으면 후보에서 뺀다. 규칙 문장을 그대로 반복할 때만 올린다.

### 산문 금지 규칙 누락 여부 (권고)

이 항목도 통과/실패를 가르지 않는 **권고 검사**다. 설명문에서 금지를 추론하면 무엇이든 후보가 되므로, 중복 항목과 정반대 방향으로 태그를 늘리라는 요구가 끝없이 나온다. 검토 후보만 올린다.

본문에 금지 규칙처럼 보이는 산문이 있는데 태그로 변환되지 않은 경우를 찾는다.
판단 단서가 되는 표현 예: "절대로", "예외 없이", "~하지 마라", "~하지 않는다", "금지".

단서에 걸렸다고 곧바로 후보로 올리지 않는다. 무검출을 통과하는 것만 후보다.
잡아내는 장치를 하나라도 지목할 수 있으면 산문으로 두는 것이 맞다.
사실 서술("확정지식 최종본에는 남지 않는다")과 규칙 서술을 가른다 -- 문장 끝이 금지형이라는 이유만으로 올리지 않는다.

### 태그 총량

파일별 태그 개수와, 파일 전체에서 태그 블록이 차지하는 문자 수 비율을 계산한다.

- [ ] 태그가 18개를 넘는 파일이 없다

초과 파일이 있으면 그 파일의 태그를 전부 나열하고, 무검출 조건으로 다시 판정한 결과를 함께 보고한다. 개수만 근거로 지우라고 제안하지 않는다.

비율은 판정 대상이 아니며 보고만 한다. 다음 검증과 비교할 수 있게 남긴다.

## 결과 보고

체크리스트 각 항목을 실행한 뒤 아래 형식으로 출력한다.

```
**태그 총량:** 파일당 최대 N개, 합계 M개, M bytes / 전체 K bytes (P%)

- [o] 항목명
- [x] 항목명 -- 실패 이유
  > "문제가 된 원문 인용"
  위치: <파일 경로> (해당 부분)
  잡는 장치: <검사 파일과 항목, 또는 절차 단계>

**결론:** 통과/실패 -- 통과 N / 실패 N
**수정 제안:** (실패 항목별 수정 방법, 없으면 생략)
```

권고 검사 둘은 통과/실패와 별개로 아래처럼 덧붙인다. 후보가 없으면 각각 생략한다.

```
**중복 검토 후보** (권고, 통과/실패 무관)
- "산문 원문" <-> 태그 "태그 원문" -- 위치: <파일 경로> -- 제안: 산문/태그 중 어느 쪽을 걷어낼지

**태그 누락 검토 후보** (권고, 통과/실패 무관)
- "산문 원문" -- 위치: <파일 경로> -- 무검출 근거: <어느 장치도 이것을 보지 않는 이유>
```

<FORBIDDEN>
`[x]` 표기 항목이 하나라도 있는데 결론을 통과로 적지 않는다.
</FORBIDDEN>
