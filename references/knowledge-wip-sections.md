# wip 섹션 규격

`knowledge-writer` 가 만들고 `knowledge-promote` 가 읽는 wip 파일의 섹션 계약. 어떤 섹션이 어떤 제목·앵커로 있고 누가 읽는지를 정한다.

writer 는 본문을 작성하기 전에, promote 는 `2. 형식 변환` 에서 이 파일을 Read 툴로 로드한다.

각 섹션 안을 어떻게 쓰는지는 여기 두지 않는다. 작성 규칙은 writer 의 해당 절(`주의점 갈래` · `예제 완결성` · `미해결 질문 조건` · `조사 보류 목록 포맷` · `서술 톤` · `버전·지원 작성 형식`)과 promote `format/format.md` 의 표기 규격이 각각 담는다.

---

## 섹션 표

`kind` 열은 그 섹션이 어느 wip 에 들어가는지다. 위에서 아래 순서로 두고, `kind` 가 맞지 않는 행은 건너뛴다. 그렇게 읽으면 concept 과 code 각각의 섹션 순서가 나온다.

| 섹션 제목 | 앵커 | kind | 내용 | 강제 / 빈 표식 | promote 소비 단계 |
|----------|------|------|------|--------------|------------------|
| 요약 | `wip:summary` | 둘 다 | 1~2 문장 핵심 | 권장 | 4. 일반화 (frontmatter `summary` 초안) |
| 본문 | `wip:body` | concept | 실제 정리. 자유로운 Markdown | 권장 | 2. 형식 변환 |
| 예시 | `wip:example` | concept | 실전 사용 사례 | 권장 | 2. 형식 변환 |
| 한 줄 정의 | `wip:definition` | code | 이 문법·기능이 무엇을 하나 | 권장 | 2. 형식 변환 |
| 문법 형태 | `wip:syntax` | code | 시그니처·구문 | 권장 | 2. 형식 변환 |
| 최소 예제 | `wip:minimal-example` | code | 돌아가는 짧은 코드 (`language` 로 작성) | 권장 | 2. 형식 변환 |
| 이전 방식과의 차이 | `wip:before-after` | code | before/after. 선행 방식이 없으면 생략 | 권장 | 2. 형식 변환 |
| 주의점 | `wip:caveats` | code | 그 기능에 실제로 있는 함정만. 갈래별로 나눠 적는다 | 권장 | 2. 형식 변환 |
| 흔한 오해 | `wip:misconception` | 둘 다 | 널리 퍼진 잘못된 통념과 그 정정 | 권장 | 2. 형식 변환 (대조·반박 포맷으로 정제) |
| 버전·지원 | `wip:versions` | code | 언어·표준 버전 기준 지원 현황 | 권장 | 2. 형식 변환 (frontmatter `since` 추출) |
| 참고 자료 | `wip:references` | 둘 다 | 외부 출처 (URL, 책, RFC, 표준 번호) | 권장 | 5. 검증 (URL 생존·표기 형식) |
| 미해결 질문 | `wip:open-questions` | 둘 다 | 확신 못 한 부분 / 사용자 판단이 필요한 열린 질문 | 강제 / `[미해결 질문 없음]` | 4. 일반화 · 5. 검증 |
| 조사 보류 목록 | `wip:pending-research` | 둘 다 | 외부 조사가 막혀 미검증으로 남긴 항목 | 권장 | 5. 검증 (출처 fetch 대조) |
| 관련 개념 | `wip:relations` | 둘 다 | 본문에서 언급한 인접 개념 | 강제 / `[관련 개념 없음]` | 3. 관계 추출 |
| 전체 예제 | `wip:full-example` | 코드 예제를 넣었을 때 | 복붙 빌드되는 완결 코드 | 조건부 강제 | 5. 검증 (컴파일·실행) |
| 캡처 맥락 | `wip:project-context` | 둘 다 | 본문 보편 서술에서 분리한 프로젝트 특유 전제·결정 | 강제 / `[전제 없음]` | 4. 일반화 |

`강제` 인 섹션은 담을 내용이 없어도 생략하지 않고 빈 표식 한 줄을 둔다. 표식 문자열은 promote 가 패턴으로 인식하므로 표의 문자열을 그대로 쓴다. `권장` 인 섹션은 해당 없으면 생략한다.

`조건부 강제` 인 `전체 예제` 는 그 wip 에 코드 예제가 있을 때만 둔다. 판정 기준은 writer 의 `예제 완결성` 이 정한다.

`미해결 질문` 의 각 항목은 해소되면 항목 끝에 `[해결 완료]` 마커가 붙는다. writer 는 이 마커를 달지 않는다 -- 승급 단계가 사용자와 항목을 닫으면서 wip 에 기록한다.

## 앵커 표기

제목 뒤 같은 줄에 공백 하나를 두고 `<!-- wip:<이름> -->` 를 붙인다. 헤딩 레벨은 강제하지 않는다.

```markdown
## 관련 개념 <!-- wip:relations -->

- 소유권과 수명
- 연속 메모리 컨테이너
```

promote 는 앵커로 섹션을 찾는다. 제목은 사람이 읽는 용도다. 앵커가 없는 헤딩은 본문 안에서 writer 가 만든 것이다.

문서에서 섹션을 지칭하는 표기도 이 경계를 따른다. wip 를 만드는 쪽(writer 정의, `knowledge-wip-protocol.md`)은 제목으로 쓰고, wip 를 읽는 쪽(promote 의 overview·`format/format.md`)은 앵커로 쓴다.

<FORBIDDEN>
앵커가 없는 섹션을 제목만 보고 그 섹션으로 판정하지 않는다.
</FORBIDDEN>

앵커는 wip 전용 표식이다. 승급 산출물에는 남기지 않는다 -- promote 가 본문을 옮길 때 함께 뗀다.
