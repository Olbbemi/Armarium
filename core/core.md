# 스킬 작성 규격

스킬을 만들거나 고칠 때 따르는 절차의 지도. 판정 기준은 여기 없고 규칙 디렉토리가 소유한다.
이 파일과 규칙이 어긋나면 규칙이 이긴다.

## 어디를 읽나

읽는 시점이 다른 것을 갈라 두었다. 필요한 것만 열고, 나머지는 열지 않는다.

| 파일 | 여는 때 |
|---|---|
| `core/verify.md` | 검증을 돌리고 결과를 읽을 때 |
| `core/rules.md` | 규칙을 만들거나 고칠 때 |
| `core/writing.md` | 문서 본문을 쓸 때 |

## 저장소의 구성

| 경로 | 담는 것 |
|---|---|
| `core/` | 툴과 무관한 절차. 이 파일이 그 지도다 |
| `rules/` | 산출물 규칙. 규칙 하나 = 파일 하나 |
| `engine/meta-rules/` | 규칙 셋과 코어를 검사하는 규칙 |
| `engine/verify.py` | 규칙을 읽어 판정기를 돌리는 엔진 |
| `engine/checks/` | 규칙별 판정기 |
| `adapters/` | 툴별 실행 차이 |
| `verify.json` | 규칙 셋 목록과 대상 종류별 경로 |
| `skills/<이름>/` | 그 스킬에서만 참인 것 |

여러 스킬이 쓸 수 있는 것은 루트에 둔다. 한 스킬에서만 참인 것만 그 스킬 아래 둔다.

규칙 디렉토리가 규칙의 소유 지점이다. 같은 규칙을 이 파일이나 `README.md` 에 다시 적지 않는다.
목록이 필요하면 `engine/gen_index.py` 로 생성한다.
