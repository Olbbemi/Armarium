대상 코드의 **플로우 facet** (facet 3)을 추출해 반환한다. 산문과 시퀀스 다이어그램을 **분리**해 반환한다.

## 입력
분석 대상 경로. 호출자(메인)가 명시 전달한다.

## 추출 항목
- **주요 시나리오 1-3개**: 진입점에서 출발하는 대표 실행 경로.
- 각 시나리오의 **호출/데이터 흐름**: 어떤 컴포넌트가 어떤 순서로 호출되고 데이터가 어떻게 오가는지.

## 출력 형식 (산문 / 다이어그램 분리)
시퀀스 다이어그램은 facet(Claude 층)에 영구 저장하지 않고 사람용 렌더에만 쓴다. 그래서 산문과 다이어그램을 한 본문 안에서 구분자로 나눠 반환한다.

- 먼저 **산문**: 시나리오마다 "왜 대표로 골랐는지" 한 줄 + 호출/데이터 흐름을 **산문만으로 이해되도록** 서술한다. Claude 는 이 산문만 읽으므로, 다이어그램 없이도 흐름이 전달돼야 한다.
- 그다음 한 줄에 정확히 `%%FLOW-DIAGRAMS%%` 구분자.
- 그 아래 **시퀀스 다이어그램**: 시나리오마다 Mermaid `sequenceDiagram` 블록 하나. 산문의 시나리오와 **같은 순서**로 두고, 각 블록 첫 줄을 `%% 시나리오 N: <제목>` 주석으로 시작해 어느 시나리오인지 표시한다.

메인은 구분자 위(산문)를 `analyze/facet/flow.md` 로, 아래(다이어그램)를 `analyze/.tmp/flow.diagram.md` 로 나눠 저장한다.

## mermaid 작성 규칙
생성한 mermaid 는 파서에서 깨지지 않아야 한다.
- sequenceDiagram 의 메시지·라벨 텍스트 안에 세미콜론(`;`)을 쓰지 않는다. mermaid 가 구문 구분자로 해석해 깨진다(쉼표 등으로 대체).
- 식별자/라벨에 `::` 같은 토큰은 피한다(예: `Event::Id` -> `Event_Id`).

## 범위
모듈 의존(facet 1), 타입 상세(2), 외부 라이브러리(4), 품질(6)은 다루지 않는다.
