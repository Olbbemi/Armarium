코드의 **데이터 계약**(영속 스키마 + 설정 스키마)을 정리해 본문으로 반환한다. 데이터 계약은 자동화 테스트 가치가 높은 영역이라(구조화된 입출력 계약) 최대 상세로 남긴다.

> **존재 조건부**: 데이터 계약이 없는 프로젝트면 그 사실만 한 줄 보고하고 빈 산출을 반환한다.

## 입력
- `analyze/facet/skeleton.md` (데이터 계약 위치 힌트).
- 분석 대상 경로.

## 산출 (data-contract.md 본문)
존재하는 것만, 도메인 무관하게:
- **영속 스키마** -- 테이블/컬렉션/엔티티의 필드명·타입·제약(PK/FK/유니크/널 허용 등), 인덱스, 마이그레이션 순서(있으면). (관계형 DB / 문서 DB / 파일 포맷 / 직렬화 계약 중 해당하는 것.)
- **설정 스키마** -- 설정 키·타입·기본값·필수 여부, 검증 규칙, 환경별 차이.
- **계약 불변식** -- 스키마가 강제하는 규칙(예: 상호배타 필드, 범위 제약). 테스트로 단언 가능한 형태로.

## 성격
스키마가 "무엇을 보장하는가"를 테스트 작성자가 바로 단언으로 옮길 수 있게 적는다. as-built.

## 출력
완성 본문을 반환한다. 저장은 메인이 `analyze/facet/data-contract.md` 에 한다.

<RICOCHET>
데이터 계약이 없으면 만들어내지 않는다. 없음을 보고한다.
</RICOCHET>

<RICOCHET>
스키마를 감싸는 어댑터의 구현 상세(시그니처)를 여기 재서술하지 않는다 -- 구조 노드 문서로 링크.
</RICOCHET>
