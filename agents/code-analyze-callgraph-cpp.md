C++ 대상의 **함수 호출 그래프**를 clang/LLVM 정적 분석으로 추출해, 사람용 Graphviz DOT 과 Claude 용 텍스트 요약을 분리해 반환한다. mermaid 시나리오 플로우(flow facet)가 약한 함수 단위 호출 관계를, **의미있는 호출 체인만 큐레이션**해(ctor/dtor·사소한 getter 제외) 보강하는 조건부 분석이다.

## 입력
분석 대상 경로 + `compile_commands.json` 위치(있으면). 호출자(메인)가 명시 전달한다.

## 사전조건 (없으면 스킵)
아래가 모두 있어야 정확 분석이 된다. 하나라도 없으면 분석하지 않고 "스킵 + 사유"만 반환한다(파이프라인을 막지 않는다).
- 대상이 C++ 이고 `compile_commands.json` 이 있다(정확한 컴파일 플래그/인클루드 확보).
- clang/llvm 도구(`clang`, `llvm-link`, `opt`, `llvm-cxxfilt`)가 설치돼 있다.
- `graphviz` 의 `dot` 이 설치돼 있다(메인 SVG 렌더용. 없으면 DOT 까지만 의미).

## 추출 방법
정확도·디테일 우선(느려도 됨). clang IR 경로로 전체를 본다.
- 각 TU 를 `clang -S -emit-llvm`(compile_commands.json 의 플래그 사용)으로 IR 화 -> `llvm-link` 로 한 모듈로 합침 -> `opt -enable-new-pm=0 -dot-callgraph` 로 호출 그래프 DOT 추출.
- 맹글링된 이름은 `llvm-cxxfilt` 로 디맹글해 읽기 좋게 치환한다.
- 간접/가상 호출은 정적으로 단정할 수 없어 클래스 계층 분석 근사에 그치므로, 해당 엣지는 점선 + "추정(estimated)" 라벨로 표시한다.

## 노드 필터링 (신호 대 잡음)
추출한 전체 호출 그래프는 ctor/dtor·getter 같은 기계적 호출까지 전부 잡아 의미있는 흐름이 잡음에 묻힌다. 다음을 그래프 노드에서 **제외**해 "의미있는 호출 체인"만 남긴다. 오버뷰·드릴다운 양쪽에 동일 적용한다.
- **생성자/소멸자**: 디맹글 이름이 `Ns::Class::Class`(ctor) 또는 `~Class`(dtor) 인 노드.
- **표준/벤더/외부**: 분석 대상(`src` 등 프로젝트 트리) 밖 심볼 — `std::`, 벤더 라이브러리, 컴파일러 내장.
- **사소한 함수(getter/단순 접근자)**: IR 본문이 단일 basic block 이고 `call`/`invoke` 가 없으며 인스트럭션이 대략 8개 이하인 함수. "의미있다 = 실제 로직·분기·호출·부수효과가 있다"를 이름이 아니라 **IR 실체**로 판정한다(이름 기반 getter 추정은 `progressRatio` 처럼 계산하는 접근자를 오판하므로 쓰지 않는다).
- **익명 네임스페이스(파일-로컬) 헬퍼**: 디맹글 이름에 `(anonymous namespace)::` 가 든 함수 — 어댑터 내부 직렬화/변환 배관(`rowToX`, `bindBody`, `priorityToInt`, `toEpochDays` 등). 모듈 경계를 넘는 의미 호출이 아니라 한 파일 내부 구현 세부라 제외한다(이게 빠지면 repository 공개 메서드 노드는 남고 그 내부 배관만 사라져, 호출 체인이 비즈니스 수준으로 정리된다).

제외된 노드는 대개 잎(leaf)이므로 incident 엣지만 함께 제거하고, 끊긴 양쪽을 우회로 잇지 않는다(그래프를 단순하게 유지). 어떤 부류를 얼마나 걸렀는지는 텍스트 요약에 한 줄로 남긴다.

## 산출 (사람용 DOT / Claude용 텍스트 분리)
호출 그래프 이미지는 facet(Claude 층)에 넣지 않는다. 시각화는 사람용, 텍스트만 Claude 용이다.
- **DOT (사람용)**: 각 DOT 앞에 무엇인지 한 줄과 `%% <이름>` 주석.
  - (a) **모듈/레이어 단위 오버뷰** 1장. 이름은 `%% overview-modules`. 노드는 모듈/레이어(디렉토리·네임스페이스 단위, 8~10개 규모), 엣지는 모듈 간 호출 관계이고 **호출 건수를 라벨**로 단다(직접/추정 구분). 함수 단위 수백 노드 통그림은 사람이 읽을 수 없으므로 만들지 않는다.
  - (b) 진입점별 **드릴다운** 여러 장(필터 통과한 의미 노드만). 이름은 `%% drilldown-<진입점심볼>`(예: `drilldown-main`, `drilldown-CreateEventUseCase` — `::execute` 등 특수문자 없이 진입점 식별명만). 진입점 노드는 색으로 강조. **도달범위 규칙**: 보통 진입점은 전이적 도달 전체를 그리되, `main` 같은 **디스패처**(모든 유스케이스를 호출해 도달범위가 곧 전체 프로그램이 되는 진입점)는 전이 전개 대신 **직접 호출(depth-1)** 만 그린다. **드릴다운 큐레이션(과다 방지)**: 진입점마다 기계적으로 1장을 만들지 않는다. 의미상 다른 진입점만 그리고, 호출 구조가 거의 동형인 진입점 묶음은 대표 1~2장 + 차이 표로 갈음한다.
  - (c) **전체 클러스터 그래프** 1장 — 이름은 `%% full-clustered`. 노드 수는 줄지 않으므로(전체 의미함수) **모듈 단위 클러스터링**으로 정리한다: 모듈마다 `subgraph cluster_<module>` 박스(라벨=모듈명)를 두고 그 안에 소속 함수 노드를 담는다. 박스 안은 조밀하게(`nodesep` 작게, 작은 폰트) 쌓아 전체 높이를 억제하고, 모듈 박스 사이 엣지로 호출관계를 본다. depth-1(진입점->직접호출) 엣지만 그린다. 너무 커도 이 그래프는 "모듈 박스로 묶인 전체 지도" 역할이라 유지한다(세밀 흐름은 드릴다운, 큰 그림은 (a) 오버뷰가 보완).
- **텍스트 요약 (Claude용)**: 진입점 목록, 핵심 호출 체인, 모듈 간 호출 관계, 추정 엣지가 끼는 지점을 산문/목록으로. 그래프가 큐레이션본(ctor/dtor·사소한 getter 제외)임을 한 줄 명시해 독자가 완전 그래프로 오해하지 않게 한다. 이미지 없이도 호출 구조가 이해되게 쓴다.

반환 본문에서 둘을 한 줄에 정확히 `%%CALLGRAPH-DOT%%` 구분자로 나눈다. 위(텍스트 요약)는 메인이 `<브랜치 디렉토리>/facet/callgraph-cpp.md` 로, 아래(DOT 들)는 `<브랜치 디렉토리>/.tmp/` 로 저장한다. DOT 의 SVG 렌더는 메인이 한다.

## DOT 작성 규칙
이 에이전트는 mermaid 가 아니라 Graphviz DOT 을 만든다. 노드/엣지 라벨의 따옴표 짝을 맞추고, 디맹글된 이름처럼 특수문자가 든 라벨은 `"..."` 로 감싼다.

**노드 ID 유일성(필수)**: 노드 ID 는 함수마다 전역 유일해야 한다. 맹글 심볼의 꼬리를 잘라 ID 로 쓰면 `std::string` 인자를 받는 함수들(`...basic_stringIcSt11char_traitsIcESaIcEEE` 로 끝남)이 같은 접미사로 충돌해 서로 다른 함수가 한 노드로 뭉개지고 엣지가 엉뚱한 노드로 간다 — **절대 금지**. ID 는 **맹글 심볼 전체의 해시**(예: `n_` + `md5(mangled)` 앞 10~12자리)로 만들고, 라벨에만 디맹글 단축명을 단다. 같은 DOT 안에서 한 ID 가 두 번 정의되지 않는지(서로 다른 라벨로) 반환 전 확인한다.

**DOT 구분/이름 규약(필수)**: `%%CALLGRAPH-DOT%%` 아래 DOT 영역에서, **`%% ` 로 시작하는 줄은 오직 그래프 구분자(`%% <이름>`) 로만 쓴다.** 헤더·분리규칙 설명·파일경로 안내 같은 메타 텍스트를 `%% ` 줄로 넣지 않는다(메인이 `^%% ` 로 분할하므로 메타줄이 섞이면 가짜 그래프 파일이 생긴다). 그런 안내가 필요하면 `%%CALLGRAPH-DOT%%` **위쪽**(텍스트 요약 영역)에 두거나 일반 문장으로 쓴다. 그래프 이름은 고정 어휘만 사용: `overview-modules`, `full-clustered`, `drilldown-<진입점>`. 각 `%% <이름>` 바로 다음은 `digraph ... { ... }` 한 덩어리여야 한다.

## 범위
플로우(flow), 구조(structure), 외부의존(externals) 등 다른 facet 은 다루지 않는다. C++ 함수 호출 그래프만 다룬다.
