C++ 대상의 **함수 호출 그래프**를 clang/LLVM 정적 분석으로 추출해, Claude 용 텍스트 요약과 뷰어용 **mermaid 그래프**를 분리해 반환한다. mermaid 시나리오 플로우(flow facet)가 약한 함수 단위 호출 관계를, **의미있는 호출 체인만 큐레이션**해(ctor/dtor·사소한 getter 제외) 보강하는 조건부 분석이다.

산출 그래프는 SVG 가 아니라 mermaid 소스다 -- 뷰어가 클라이언트에서 mermaid 로 렌더한다. graphviz 는 쓰지 않는다.

## 입력
분석 대상 경로 + `compile_commands.json` 위치(있으면). 호출자(메인)가 명시 전달한다.

## 사전조건 (없으면 스킵)
아래가 모두 있어야 정확 분석이 된다. 하나라도 없으면 분석하지 않고 "스킵 + 사유"만 반환한다(파이프라인을 막지 않는다).
- 대상이 C++ 이고 `compile_commands.json` 이 있다(정확한 컴파일 플래그/인클루드 확보).
- clang/llvm 도구(`clang`, `llvm-link`, `opt`, `llvm-cxxfilt`)가 설치돼 있다.

graphviz `dot` 은 더 이상 필요 없다(SVG 렌더를 하지 않고 mermaid 소스만 낸다).

## 추출 방법
정확도·디테일 우선(느려도 됨). clang IR 경로로 전체를 본다.
- 각 TU 를 `clang -S -emit-llvm`(compile_commands.json 의 플래그 사용)으로 IR 화 -> `llvm-link` 로 한 모듈로 합침 -> `opt -enable-new-pm=0 -dot-callgraph` 로 호출 그래프를 뽑아 **엣지 목록**을 얻는다(DOT 은 엣지 추출 중간물일 뿐 산출이 아니다).
- 맹글링된 이름은 `llvm-cxxfilt` 로 디맹글해 읽기 좋게 치환한다.
- 간접/가상 호출은 정적으로 단정할 수 없어 클래스 계층 분석 근사에 그치므로, 해당 엣지는 mermaid 점선(`-.->`) + "추정(estimated)" 라벨로 표시한다.

## 노드 필터링 (신호 대 잡음)
추출한 전체 호출 그래프는 ctor/dtor·getter 같은 기계적 호출까지 전부 잡아 의미있는 흐름이 잡음에 묻힌다. 다음을 그래프 노드에서 **제외**해 "의미있는 호출 체인"만 남긴다. 모든 그래프에 동일 적용한다.
- **생성자/소멸자**: 디맹글 이름이 `Ns::Class::Class`(ctor) 또는 `~Class`(dtor) 인 노드.
- **표준/벤더/외부**: 분석 대상(`src` 등 프로젝트 트리) 밖 심볼 -- `std::`, 벤더 라이브러리, 컴파일러 내장.
- **사소한 함수(getter/단순 접근자)**: IR 본문이 단일 basic block 이고 `call`/`invoke` 가 없으며 인스트럭션이 대략 8개 이하인 함수. "의미있다 = 실제 로직·분기·호출·부수효과가 있다"를 이름이 아니라 **IR 실체**로 판정한다(이름 기반 getter 추정은 `progressRatio` 처럼 계산하는 접근자를 오판하므로 쓰지 않는다).
- **익명 네임스페이스(파일-로컬) 헬퍼**: 디맹글 이름에 `(anonymous namespace)::` 가 든 함수 -- 어댑터 내부 직렬화/변환 배관. 모듈 경계를 넘는 의미 호출이 아니라 한 파일 내부 구현 세부라 제외한다.

제외된 노드는 대개 잎(leaf)이므로 incident 엣지만 함께 제거하고, 끊긴 양쪽을 우회로 잇지 않는다(그래프를 단순하게 유지). 어떤 부류를 얼마나 걸렀는지는 텍스트 요약에 한 줄로 남긴다.

## 산출 (Claude용 텍스트 / 뷰어용 mermaid 분리)
반환 본문을 한 줄에 정확히 `%%CALLGRAPH-DIAGRAMS%%` 구분자로 나눈다. 위(텍스트 요약)는 메인이 `<브랜치 디렉토리>/facet/callgraph-cpp.md` 로, 아래(mermaid 그래프들)는 메인이 **facet 에 지속**한다(`<브랜치 디렉토리>/facet/callgraph.diagrams.md`). facet 에 지속하는 이유는 render 를 facet 로부터 재시작할 수 있어야 하고, callgraph 는 툴체인 재실행 없이는 재생성 불가라 소스가 남아야 하기 때문이다(render-data 는 이 소스를 그대로 data.js 로 복사한다).

- **텍스트 요약 (Claude용)**: 진입점 목록, 핵심 호출 체인, 모듈 간 호출 관계, 추정 엣지가 끼는 지점을 산문/목록으로. 그래프가 큐레이션본(ctor/dtor·사소한 getter 제외)임을 한 줄 명시해 독자가 완전 그래프로 오해하지 않게 한다. 이미지 없이도 호출 구조가 이해되게 쓴다.
- **mermaid 그래프 (뷰어용)**: 각 그래프 첫 줄에 `%% <이름>` 을 달고 그 아래 mermaid 소스 한 덩어리를 둔다. 이름은 고정 어휘만 -- `overview-modules`, `drilldown-<진입점>`, `full-clustered`.
  - (a) **모듈/레이어 오버뷰** 1장 (`%% overview-modules`). 노드는 모듈/레이어(디렉토리·네임스페이스 단위, 8~10개 규모), 엣지는 모듈 간 호출 관계이고 **호출 건수를 라벨**로 단다(직접/추정 구분). 함수 단위 수백 노드 통그림은 만들지 않는다. 기본 노출.
  - (b) 진입점별 **드릴다운** 여러 장 (`%% drilldown-<진입점>`, 예: `drilldown-main`). 필터 통과한 의미 노드만. 진입점 노드는 색으로 강조. **도달범위 규칙**: 보통 진입점은 전이적 도달 전체를, `main` 같은 **디스패처**(모든 유스케이스를 호출해 도달범위가 곧 전체 프로그램이 되는 진입점)는 **직접 호출(depth-1)** 만 그린다. **드릴다운 큐레이션(과다 방지)**: 진입점마다 기계적으로 1장을 만들지 않는다. 의미상 다른 진입점만 그리고, 호출 구조가 거의 동형인 묶음은 대표 1~2장 + 차이 표로 갈음한다. 부피가 크므로 기본 접힘.
  - (c) **전체 클러스터 그래프** (`%% full-clustered`) -- 모듈 단위 `subgraph` 로 묶어 전체 호출 지도를 담는다. 단 mermaid 는 초대형 그래프 레이아웃이 약하므로, **의미 노드 수가 대략 60 이하일 때만** 만든다. 넘으면 이 그래프는 생략하고(오버뷰 + 드릴다운으로 충분), 생략 사실을 텍스트 요약에 한 줄 남긴다. 만들면 기본 접힘.

## mermaid 작성 규칙
graphviz DOT 이 아니라 mermaid `graph` 를 만든다.

**노드 ID 유일성(필수)**: 노드 ID 는 함수마다 전역 유일해야 한다. 맹글 심볼의 꼬리를 잘라 ID 로 쓰면 `std::string` 인자를 받는 함수들이 같은 접미사로 충돌해 서로 다른 함수가 한 노드로 뭉개지고 엣지가 엉뚱한 노드로 간다 -- **절대 금지**. ID 는 **맹글 심볼 전체의 해시**(예: `n_` + `md5(mangled)` 앞 10~12자리)로 만들고, 라벨에만 디맹글 단축명을 단다. 같은 그래프 안에서 한 ID 가 두 라벨로 두 번 정의되지 않는지 반환 전 확인한다.

**라벨 따옴표(필수)**: 노드 라벨(`n_abc["..."]`)과 엣지 라벨(`-->|"..."|`)을 예외 없이 따옴표로 감싼다 -- 디맹글 이름의 `( ) < > :: ,` 등이 파서와 충돌해 깨진다. 태그로 먹을 `<` 는 `&lt;` 로 이스케이프한다.

**구분/이름 규약(필수)**: `%%CALLGRAPH-DIAGRAMS%%` 아래에서 `%% ` 로 시작하는 줄은 오직 그래프 구분자(`%% <이름>`)로만 쓴다. 헤더·설명·경로 안내 같은 메타 텍스트를 `%% ` 줄로 넣지 않는다(메인이 `^%% ` 로 분할하므로 메타줄이 섞이면 가짜 그래프가 생긴다). 각 `%% <이름>` 바로 다음은 mermaid `graph ...` 한 덩어리여야 한다.
