외부 의존을 **단일 소스 레지스트리**로 정리해 본문으로 반환한다. 이 문서가 의존성 인벤토리의 척추이고, architecture/구조 노드는 여기로 링크만 한다.

> 스코프 노트: externals 는 테스트보다 **리팩토링**(라이브러리 업그레이드/교체) 축에서 밥값을 한다. 유닛테스트 모킹 시임은 외부 라이브러리가 아니라 포트(구조 facet)가 잡으므로, 여기서는 "어느 의존이 포트 뒤에 있고 어느 게 직접 샜나"를 짚는 게 테스트 관점의 고유 가치다.

## 입력
- `analyze/facet/skeleton.md`.
- 분석 대상 경로(의존 선언 파일 -- 패키지 매니페스트/락 파일/벤더 디렉토리 등).

## 산출 (externals.md 본문)
레지스트리 표, 의존마다:
- **라이브러리/패키지명 + 버전**.
- **용도** -- 무엇에 쓰나(한 줄).
- **감싸는 어댑터/사용 위치** -- 어느 파일/모듈이 이걸 쓰나(구조 노드로 링크).
- **벤더링** -- in-tree vendored 인지 외부 의존인지.
- **포트유무 칼럼** -- 포트(경계 인터페이스) 뒤로 추상화됐나(깨끗·교체가능·테스트가능) vs 포트 없이 코어/엣지로 직접 의존(숨은 테스트 시임). 후자는 명시 플래그.

## 성격
벤더/서드파티 코드 **자체를 분석하지는 않는다**(비효율). 무엇을/몇 버전/어디서/어떻게 경계 짓나까지. as-built.

## 출력
완성 본문을 반환한다. 저장은 메인이 `analyze/facet/externals.md` 에 한다.

<PENETRATE>
각 외부 의존에 "포트 뒤 추상화 vs 직접 의존(숨은 시임)" 여부를 칼럼으로 명시한다.
</PENETRATE>

<RICOCHET>
벤더/서드파티 라이브러리 내부 구현을 분석해 정리하지 않는다(경계까지만).
</RICOCHET>

<RICOCHET>
같은 라이브러리 정보를 architecture/구조 노드에 중복으로 적게 두지 않는다.
</RICOCHET>
