골격을 입력으로 받아, **자기 소유 서브트리의 소스 파일마다 노드 문서 1장**을 채워 자기 소유 facet 파일에 직접 Write 한다(본문으로는 쓴 경로 목록만 반환). 타입/함수의 전체 시그니처 + 속성(역할/불변식/예외)을 담는다. 이 문서가 구조 상세의 **단일 소유처**이고, 가로지르는 문서(flow/architecture 등)는 여기로 링크만 한다.

> 규모 적응: 트리가 작으면 한 에이전트가 전체를, 크면 모듈/서브트리당 한 에이전트가 **겹치지 않는 파일만** 소유한다. 메인이 호출 시 소유 경로 목록을 준다.

## 입력
- `analyze/facet/skeleton.md` (공유 사실: 파일 트리/인벤토리/개수).
- 이 에이전트가 소유한 서브트리/파일 경로 목록.

## 산출 (파일노드당 1문서)
노드 = 소스 파일 1개(선언/정의가 분리된 언어면 같은 단위로 묶어 파일 1개 = 문서 1개). 각 노드 문서에:
- 그 파일이 담은 **타입**(구조체/클래스/인터페이스/열거형): 멤버 + 메서드, **상속/구현 관계**.
- **자유 함수**.
- 각 타입/함수의 **전체 시그니처**: 인자명+타입, 반환, 한정자(const/static/virtual/override 등 언어별), 가시성.
- 각 항목의 **속성 3**: 역할/책임(최대 상세), 불변식/사전조건, 예외 계약.

## 커버리지/깊이 규율
- **커버리지 망라**: 사소한 접근자(getter)도 빠짐없이 등장시킨다(목록은 골격 인벤토리와 일치해야 함).
- **깊이 비례**: 분량은 복잡도에 비례한다 -- 사소 getter 는 한 줄, 핵심 로직은 풀 상세. 망라는 커버리지 기준이지 분량 기준이 아니다.

## 성격
의도가 아니라 as-built. 골격이 준 이름/개수 위에 **깊이만** 더한다.

## 출력 (직접 Write)
자기 소유 노드 문서를 `analyze/facet/<소스미러>/<노드>.md` 에 **직접 Write** 하고, 본문으로는 **쓴 파일 경로 목록만** 짧게 반환한다(노드 내용을 본문으로 돌려주지 않는다). 구조 노드는 수가 많아(서브트리당 수십 개) 본문으로 돌리면 메인 컨텍스트/턴을 크게 먹으므로, 렌더와 같은 "직접 Write" 부류다. 골격 대비 교차검산은 메인이 Stage 2 에서 한다.
